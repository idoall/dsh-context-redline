# dsh-context-redline（上下文批改台）

> **DeepSeek Harness 插件**：把「上下文」从**只读的仪表盘**变成**人能批改的工作台**，
> 并把「编辑 → 快照 → 子会话 → 压缩 → 主会话指挥子会话」串成一条主线，
> 用来**切断上下文膨胀**，并让**注入漂移"看得见、能人工处理"**（只做检测 + 显式重注入，**不承诺自动避免漂移**）。

**当前状态：只有文档，还没有代码。** 本仓库现在处在 **M0（文档先行）**：
范围、平台事实、架构、界面规格、路线图、测试计划都已经写成文档，等评审与拍板之后才开工。
为什么这样做：先把"要做什么、依据是什么、做到什么算完成"写清楚，比先写代码再解释便宜得多。

---

## 它要解决什么

| 问题 | 现象 | 本插件的答案 |
|---|---|---|
| **上下文膨胀** | 每次请求把全部历史重发，会话越跑越大 | **开子会话 + 显式压缩**：子会话继承已完成历史，再由你在它里面压缩 |
| **注入漂移** | 宿主每轮重新注入 `runtime-context` / AGENTS.md / 技能目录，人改掉的下轮又回来 | **改完立刻写进上下文**（遮蔽旧口径）→ 再用改好的上下文**开子会话**接着干 |
| **改不动** | 上游的上下文浏览器只能看，不能改 | **右侧直接编辑**：改哪一条、改了什么、生效没有，一眼可见 |

**一句话**：**改上下文**（编辑 / 批注）→ **用改好的它开子会话**接着干。就这么简单。

## 它长什么样

界面外壳**整体来自上游 [`dsh-context`](https://github.com/bowenliang123/dsh-context)**：**源码复制基线 = git tag `v0.59.2`**；
而你现在正在用的那个面板是**实装的 `dsh-context@0.60.0`**（两者是两件事），本插件与它**并存**：
我们在这套界面上加的是**编辑能力**与**编排能力**：

- **左侧**：趋势图的轮次条上直接标「用户消息 N · 注入内容 N」；点某一轮 → 右侧切到该轮末步
- **右侧**：分类展开（系统提示词 / 工具定义 / 用户消息 / 注入内容 / 技能注入 / 助手消息 / 工具结果）
  - 每行有 `#事件序号` 与动作：**编辑**（保存 = 只写本地）/ **批注**（存一条本地更正）/ （有本地改动时）`已保存（本地）` + `丢弃这条改动`
  - 编辑器**在那一行下面内联展开**（不弹窗），预填的是**完整正文**
- **下方**：子会话（**开子会话** → 它继承已经聊完的历史；看状态与来源。压缩 / 打断去官方视图里做）
  —— 新会话**永远从"最后聊完的那一轮"开始**，**没有任何参数**能挑更早的位置（见 [`docs/01`](docs/01-platform-facts.md) F38）；用户 2026-10-02 据此把"冻结记录"整套删掉了（`docs/11` D10）
  **最后一个已完成轮次末**，更早的记录**分不出来**（见 [`docs/01`](docs/01-platform-facts.md) F38）。

## 四条必须让人一眼明白的规则

1. **只有「已注入」的内容才进模型**。
2. **两种改法，后果不同**：
   - **编辑 = 遮蔽原文**：模型再也看不到原文（原文仍在日志里，**可回滚**）
   - **批注 = 保留原文**：追加一条带「作废范围」的更正，模型两者都看到
3. **所有保存都是临时保存**（硬约束）：点「保存」→ 只写插件本地，**当前会话的模型看不到**。改动只有在点「开启子会话」时，才逐字写进那个新会话的第一句话。
4. **哪些能改，由平台能力决定**（实测）：
   - 可改写：**用户消息**、注入内容、技能注入（底层是 user/tool 时）、工具结果
   - **不可改写：助手消息**（平台两条规则互斥）→ 只给「批注」，界面明说原因
   - **可以连续改、可以回滚**：版本历史里选一版恢复即可（不是"只能改一次"）

## 明确不做

- ❌ 不做"删除历史"（DSH 的会话日志是 append-only；能做的只有**遮蔽**与**压缩**，后者不可逆）
- ❌ 不自动开子会话 / 不自动重注入 / 不自动提交草稿
- ❌ 不产生任何 **AI 生成内容**（这是本项目存在的理由：进模型的每个字都必须来自人）
- ❌ 本轮不做"上下文装配/模板/组装"那一套（那是另一个数据模型，见 [`docs/00`](docs/00-scope.md) §4）
