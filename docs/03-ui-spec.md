## 0. 与上游的关系（先定"不改什么"）

> ⚠️ **按钮集合由能力开关驱动**：M4.5（`docs/04`）会把平台能力验成一组布尔量
> （`sessionQuery` / `agents` / `fork` / `compaction` / `rollbackHistory`）。
> **任何一个为 false，本规格里对应的按钮就必须不存在**（而不是"存在但点了报错"），
> 且 `docs/00` 的 S10 表给出该开关为 false 时 S 条的口径。**本文件里凡是写"给按钮"的地方，都隐含"能力为 true"。**

**布局与信息架构整体沿用上游**（图 1 就是它）：这是一个**两列**页面，不是单列。

- 左列：上下文统计 / Token 统计 / 当前上下文 / 上下文趋势 / 「第 N 轮 · 第 M 步」/ 上下文事件 / 文件活动
- 右列：插件信息 / 耗时统计 / **上下文浏览器** / 文件活动

> 本插件在右列**新增两张卡片**：「固定块（不变量）」（R2.4，注入类的钉子）与「快照与子会话」（R5.1），
> 位置都在**上下文浏览器下方**（不挤掉上游那几块）。
>
> 归档 v1 那份"一列居中、上限 `min(100% - 32px, 920px)`"的规格**不适用**于本页面（那是 v1 单列设计的约束）。
> 本页面里的宽度约束只用于**行下内联编辑器**与**确认条**。

**上游已经做对、我们不动的东西**（避免重做）：
分类行（条数 / token / 占比 / 与上一轮末步的 δ）、逐元素展开、`#seq` 之外的折叠/展开、DNA 模式、文本过滤、`/context` 弹窗（弹窗里**不挂编辑**，保持与上游完全一致）。

## 1. 左侧：轮次 → 右侧（本插件最大的一处 UI 增量）

### R1.1 轮次选择驱动右侧
点趋势图的**轮次条**，或点「第 N 轮 · 第 M 步」卡片 → 右侧浏览器切到**该轮末步**。
- 一个轮次有多个 step，**没有"轮次本身的 surface"**这个实体（平台事实：`SurfaceNode` 只有 `seq` 没有 `turn`）。所以规则写死为：**轮 → 该轮最后一个 step**，并在标题里**说出来**。
- 标题格式：`第 25 轮（共 1 步，显示末步）`。
- **不得**复用上游的 `pinSeq` prop 来实现（上游每次 `pinSeq` 变化会重置手风琴展开状态）；要新增一个独立的 `turnSel` 语义。

### R1.2 轮级与步级并存
- 保留上游的步级下拉（`当前（下一次请求）` + 每个 step）。手动在下来里选一个 step = 退出轮级选择（标题变回 `第 T 轮 · 第 S 步 (共 N 步)`）。
- 悬停趋势图（预览）与钉住（`pinSeq`）行为**不变**。

### R1.3 左侧每轮显示"有多少内容注入"
- 轮次条/轮次列表上，每轮显示两个数字：**用户消息 N** 与 **注入内容 N**（同一套配色：用户消息 = 绿、注入内容 = 紫，与上游 `CATS` 一致）。
- 数字来自 `RequestRecord` 的分类 token 计数（上游已有）→ **不新增服务端查询**。
- 若空间不足（窄屏）：**只显示注入内容条数**（用户最关心的"漂了没有"信号），并在 title 里给全。

### R1.4 「改这一轮的用户消息」快捷入口
在「第 N 轮 · 第 M 步」卡片上放一个次级动作：点它 → 右侧切到该轮末步 → **展开「用户消息」分类** → 滚到**该轮最后一条用户消息**并把编辑区展开（预填**全文**，见 R3.4）。
- 若该轮没有用户消息 → 按钮置灰 + title 说明"这一轮没有用户消息"。
- ⚠️ **实现上的硬要求**（2026-10-01 实测踩过）：这一动作必须**直接调用一个函数**完成上述三件事，
  **不得**写成"去点另一个卡片里的某个元素"（旧实现是 `document.querySelector('[data-turn=N]').click()`，
  而 `[data-turn]` **只在"按步骤"模式的轮次刻度格里才有** → 默认的按轮次模式下点了等于没点；
  用户原话："按钮点击了没有效果？"）。

### R1.5 趋势图的**粒度开关**：按轮次 / 按步骤（默认按轮次）

- 按轮次：一轮一根柱（合并该轮各步，取**末步**；柱下方标该轮步数）。点柱子 = 选中这一轮（右侧显示该轮**末步**）。
- 按步骤：一次请求一根柱。点柱子 = 选中那一步。
- 标题必须把规模写出来：`按轮次（共 28 轮）` / `按步骤（共 72 次请求）` —— **用户要能一眼看出"有多少轮"，而不是只看到最后几轮**。
- 参照：参考插件 `trendChart` 的 `granularity: 'step' | 'turn'`。

### R1.6 趋势图的**模式开关**：总计 / 增量（默认总计）

- 总计 = 该次请求的上下文量；增量 = 比上一次请求多了多少。
- **增量可以为负**（压缩 / 裁剪之后上下文变小）：**围绕零线**画 —— 涨的段在零线**上方**、跌的段在**下方**，
  **颜色仍然是类别**（方向表示正负，不是"变红"）。不得把负值截断成 0。
  **零线位置按 `maxUp : maxDown` 成比例分割柱区**（照参考插件 `trendChart.tsx` 的原话：
  "the zero line splits the bar area PROPORTIONALLY to the larger side, so the px-per-token scale is
  identical above and below it"）—— 否则上下两截每像素代表的量不同，读起来会骗人。

### R1.7 **自适应刻度**（默认开）

- 打开：纵轴上限只按**当前可见的那几根柱**算；关闭：按整段历史算。
- 理由：长会话里远处的一个尖峰，会把眼前这些柱子全压成一条线。滚动时要跟着重算。

### R1.8 **聚焦某一类**

- 点分类树里某一类的色块 → 趋势图只画该类并重新缩放；标题显示 `聚焦：注入内容（全部）`，点"全部"恢复。
- 再点同一个色块 = 取消聚焦。

### R1.9 **固定柱宽 + 横向滚动**（不许"压缩到看不清"）

- 柱宽固定（14px），**不随轮数变窄**；柱多了就横向滚动。
- 横向滚动容器：`overscroll-behavior-x: contain`，并在 WebKit 上**取消**到边后的横向 wheel ——
  否则在手机上滑到趋势图边缘会触发"左滑返回"，把整个界面带走（参考插件 `overscroll.ts` 就是为这个）。
- 选中柱子被滚动到可视区内（居中），并提供 `回到当前` 一键滚到最右。

### R1.10 **轮次分组刻度带**（按步骤模式）

- 柱子下面按轮分组的刻度带：每格宽度 = 该轮步数，格内标轮号（悬停给"第 N 轮（共 k 步）"）。
- 点一格 = 选中该轮末步。按轮次模式下刻度带按柱对齐，仅作标号。

### R1.11 **步级快捷片 + 顺序导航** —— ⛔ **已作废（用户 2026-10-01 决定）**

> **原文（保留备查）**：当前轮的每一步一片 `第 1 步 / 第 2 步 / …` + `当前（下一次请求）`；
> `◀ 上一轮 / 下一轮 ▶`、`◀ 上一步 / 下一步 ▶`；`←/→` 键等价于上一步/下一步。
>
> **为什么删**（用户原话）："这些没有太大意义，因为用户鼠标移上去了……移到柱体上自然就看到了，
> 点『上一步』『下一步』帮助不大。反而会给用户造成干扰。" ⟹ 柱子 hover 即报"第几轮 · 第几步"、
> 点一下即选中，那一排只是重复信息。
> **保留**：柱子下面那行**轮号刻度带**（R1.10）—— 它是图表的坐标轴，不是导航。
> **连带**：`←/→` 快捷键一并取消；步级选择仍然可以在**右侧的步骤下拉**（R1.13）里做。

### R1.12 **压缩 / 剪枝标记 ✂**（一个事件 = 一根柱，绝不重复）

- **一个事件只标在「它之后的第一个请求」那一根柱子上**（照参考插件 `attachMarkers`：找到第一个 `seq >= 事件 seq` 的请求就 `break`）。
  ⚠️ 不许"标在它之后的每一根柱子上" —— 那会让 2 个事件显示出 3 个剪刀（本插件实际踩过这个坑，冒烟测试现在锁死这一点）。
- **按轮次**模式：一轮只有一根柱，把该轮各步的标记**合并**到这一根上；一轮里有多个事件时显示 `✂×N`（不许把事件吞掉）。
- **✂ 自身也必须有提示**：鼠标移上去（或键盘聚焦）显示与该柱相同的那张提示卡，其中逐条列出事件：
  `✂ 压缩：压缩上下文（摘要替换 N 条消息）` / `✂ 剪枝：剪枝工具输出`。
  点 ✂ = 跳到那一次请求（与点柱子同效）。**没有说明的图标等于没做** —— 用户第一次看到时就是这么问的。
- 事件类型文案：`compaction` = **压缩**、`prune` = **剪枝**（与参考插件 i18n 的 `kind.compaction` / `kind.prune` 一致）。
- 左下「上下文事件」卡片列出每个事件：`#seq · ✂ 类型 · 说明 → 标在第 T 轮 · 第 S 步`，与柱子上的标记是同一条。

### R1.12.1 「上下文事件」卡：**会变的**与**不变的**必须分开呈现

- **会变的**（随你选的位置变化）做成**事件行**：每行给 `✂` 图标、事件名、它的说明、发生在第几轮第几步，
  以及状态徽章 **`已发生`（实心、左侧品牌色竖条）** / **`尚未发生`（虚线、降透明度）**。
  顶部一行汇总：`看的是 第 N 轮 · 第 M 步 这一刻 · 已发生 X · 还没发生 Y`。
- **不变的**（这一栏到底干什么用）收成**底部一行小字**，不占视觉重量。
- 用户 2026-10-01 的两条原话："内容是不变的，不拟真"＋"都堆在一起、都是这种浅灰色，不是很醒目"。
- 位置一变，`已发生/尚未发生` 的划分必须跟着变（同一会话早期那一步会看到"尚未发生"）。

### R1.13 右侧的轮/步选择器

- 两个下拉：**轮次**（每项标"（共 N 步）"）与**步骤**（只列该轮的步 + `当前（下一次请求）`）。
- 与左侧趋势、右侧步骤下拉**两者**必须始终一致（交叉比对应当逐项相同；R1.11 的步级快捷片已作废）。

### R1.14 趋势图的 hover 提示（**自绘**，一律不用原生 `title`）

- 鼠标移上去、或键盘聚焦柱子时**立刻**出现 2 行提示；提示 `pointer-events: none`，不许挡住柱子。
- **第一行 = 位置**（两种粒度的文案不同，逐字照参考插件）：
  - 按步骤：`第 {t} 轮 · 第 {s} 步 (共 {n} 步)`
  - 按轮次：`第 {t} 轮 · 共 {n} 步`（该轮只有 1 步时写 `第 {t} 轮 · 共 1 步`）
- **第二行 = 数值**：`合计 ≈ {n}`；聚焦某类时 `{类别} ≈ {n}`；增量模式 `Δ {n}`（带正负号）。
- 该柱若挂有压缩/裁剪标记，**再加一行** `✂ {事件名}`。
- **必须渲染在横向滚动容器之外**：放在滚动内容里会撑大 `scrollWidth`，导致 hover 时滚动条开合、整张卡片跳动；
  提示用 `transform` 夹在可视区内（左右都不越界）。
- **触屏没有 hover**：点柱子选中后提示**常显**（换一根或滑走才消失）→ 手机上同样能看到"第几轮/第几步"。
- 原生的 `title` 一律不用（有延迟、手机上不出现）—— 照参考插件的做法。

### R1.15 柱体 = **按类别分色堆叠**（照参考插件 `dsh-context` 的 `lc-cat-seg`）

- 每根柱子不是"一根单色柱"，而是**按右侧分类树的那一套类别切段**：颜色 = 类别（与分类树同源同色），
  段高 = 该类这次在该柱里的量；只有非零的类别才产生段。
- 总计模式：段自下往上堆（顺序与分类树一致）。增量模式：见 R1.6（正差向上、负差向下，颜色仍是类别）。
- 聚焦某一类（R1.8）时**只保留那一类**的段（其余不画），于是"聚焦"这件事在图上变得可见。
- **反例（不许再出现）**：整根一个品牌色 + 负数涂红 —— 那既看不出上下文构成，也让"增量"失去意义
  （用户 2026-10-01 明确要求照参考插件的做法）。

### R1.16 「改这一轮的注入内容」快捷入口（R1.4 的**对称**入口）

> 用户 2026-10-01：**编辑不只是用户消息** —— 注入内容（`AGENTS.md` / memory / runtime-context / 技能目录…）
> 才是 AI 最容易理解错的那一半；而且它**每轮由宿主重新注入**，改一轮漂一轮。

- 步骤卡上与 R1.4 并排再放一个次级动作：点它 → 右侧切到该轮末步 → 展开「注入内容」类 →
  滚到**该轮最后一条注入内容**并把编辑区展开（预填全文）。
- 该轮没有注入内容 → 按钮置灰 + title 说明。
- 实现同样**直接调一个函数**，**不得**跨卡片点按（同 R1.4 的硬要求，见 `docs/10` M05-32）。

## 2. 右侧：行模型与动作条

### R2.1 哪些行有动作（**由实测能力决定，不是设计偏好**）
| 分类 | 编辑（改写） | 批注 | 存为不变量 | 说明 |
|---|---|---|---|---|
| 系统提示词 | ❌ | ❌ | ❌ | 上游该行不传节点对象；且宿主保护 node 0 的 system（`assertSystemHeadRewrite`） |
| 工具定义（schema） | ❌ | ❌ | ❌ | 它们是请求头里的 schema 行，不是 surface 节点 |
| **用户消息** | ✅ | ✅ | ❌ | **本插件的关注重点**；实测可连续改任意次 |
| **注入内容** | ✅ | ✅ | ✅ | 这类每轮会被宿主重新注入 → 改一轮漂一轮，必须引导固定 |
| 技能注入 | ⚠️ 看底层事件类型 | ✅ | ✅ | 底层是 `user/message` / `tool/result` → 可改写；底层是 `assistant/message` → **只能批注**。按钮由宿主给的 `type` 决定，不由 `cat` 猜 |
| **助手消息** | ❌ **不给「编辑」** | ✅ | ❌ | **平台两条规则互斥，assistant 的 replace 不可能成功**（`docs/01` F7.2）。给了按钮必然点下去报错 |
| 工具结果 | ✅ | ✅ | ❌ | 只能改内容文本与错误标记（宿主只允许改 `content`） |

> 按钮的**可见性分两档**（常用 / 高级）见 **R2.5**：注入内容与技能注入属常用档（每轮被重新注入、会漂，必须始终可见），
> 工具结果的「编辑」属高级档（默认收起，但留标记说明在哪打开）。
>
**助手消息为什么没有「编辑」**：按钮位置改为显示一个说明徽章，title 写明
「助手消息在平台上无法改写（两条规则互斥）。要纠正它请用「批注」；要重建上下文，用「快照 + 子会话」。」
（**不承诺**"遮蔽整段"：多节点区间替换平台可行，但**不在 v1 的 UI 范围内**，见 §8 与 `docs/01` V9）

> **这些改动怎么进"后期的上下文快照"**（用户 2026-10-01 问："还有哪些内容可以编辑，作为后期的上下文快照吗？"）
>
> - **只有「已生效」（`应用到会话` 过）的改动才进快照 / fork 种子**；**草稿只在插件本地** ——
>   所以 R5.2 硬拦"有草稿时不许冻结 / 开子会话"（`docs/06` §2）。
> - **改写不是删除原文**，而是往日志追加一条替换事件：种子里模型看到的是改后的内容，原文仍在日志里（可用 R4.5 版本历史回滚）。
> - **批注**是追加一条更正消息：**原文保留、模型两者都看到**；它不需要 `apply`，写下去就在日志里 → 也就进快照。
> - **固定块（不变量）不自动进种子**：它是一份逐字原文，用来做漂移比对与显式重注入；冻结记录里会记下"当时在效的固定块版本"（R2.4 / R5.1）。
> - **系统提示词 / 工具定义改不了**（它们不在 surface 里，且宿主保护 system）→ 要改这两类属于**装配层**（人格 / 指令 / preset），本轮不做（`docs/00` §4.1、M7）。
> - **助手消息改不了**（平台两条规则互斥，`docs/01` F7.2）：想纠正它只能用**批注**（追加更正），或重建上下文（快照 + 子会话）。>
> **其中「批注」在快照 / 子会话里起什么作用**（用户 2026-10-01 单独问过这件事）：
>
> 1. 它是一条**普通 `user` 消息**（正文自带结构化头部：更正目标 / 作废范围 / 理由 —— **不是**伪造宿主内容），
>    追加进日志之后**就在快照的种子里**，子会话开场就能读到它。
> 2. 它**对被批注的那条没有任何机械作用**：不遮蔽、不替换 —— 模型看到的是「原文 + 你的更正」两条并存（`docs/01` F6）。
> 3. 所以它的作用是**请求式**的：靠措辞让模型照做，**平台不保证**。
>    要"确定生效"必须用 **`编辑` → `应用到会话`**（遮蔽原文，模型只看到改后的那一条）。
> 4. 它**不会漂移**（不同于每轮被重新注入的注入类），但**会被压缩波及**：压缩是把一段历史摘要替换 →
>    这条更正可能不再逐字存在。要长期有效，请存成**固定块**并按需重注入（R2.4）。
> 5. 子会话**不知道"这条曾被批注过"**：没有批注继承链，它只是读到那条消息本身 ——
>    这正是批注正文必须自带「更正目标 / 作废范围」的原因。
> 6. 因此 **R3.3.1** 要求「提交更正到会话」**同样先出确认框**，并在框里把上面这些写清楚（demo 已实现，见 `demo/screenshots/annotate-confirm.png`）。


### R2.2 动作条（行内，常驻可见）
顺序固定：`#seq` → （有草稿时）`未生效` → `编辑` → `批注` → `存为不变量`（仅注入类）→ `应用到会话`（仅有草稿且轮次闭合）

- **常驻可见**，不许只靠 hover（手机没有 hover）。
- 每个按钮都要 `title`，回答三件事：**这是什么 → 会发生什么 → 能不能撤回**。
- 按钮必须放在行的 `<button>`（展开正文）**之外**，并 `stopPropagation`，否则点「批注」会顺带展开正文（看起来像点错了）。
- 触控目标 ≥ 44×44（窄屏 640px 以下按上游 `redline.css` 的做法放大）。
- **动态出现的按钮必须带「?」标记**（用户 2026-10-01 提的做法）：讲解模式的编号是按"元素类别"固定编号的，
  而**点开之后才出现**的按钮（编辑器里的 `保存草稿`/`提交更正到会话`/`保存为固定块`/`取消`、确认框里的 `确认`）
  拿不到稳定编号 —— 所以它们需要 `?`：点它弹出与讲解模式**同一份说明**（做什么 / 会发生什么 / 能不能撤回 / 要不要确认 / 对应哪条 R）。
  ⚠️ **做成「贴着元素左上角飘的小圆标」**（与讲解模式序号 `.exnum` **同一种做法**：`position:absolute; top:-9px; left:-8px`，
  外层 `.qwrap{position:relative}`），**不是**在按钮后面再挂一个独立按钮 ——
  用户原话：「不是在按钮后面单独加一个问号……这么做，至少用户体验上看着很差。我们虽然做的是 demo，但要尽量拟真。」
  **没有说明的按钮等于没做。**

### R2.3 不能编辑时必须给原因（不许按钮凭空消失）
**判定按"行身份"**（是不是当前可见节点、底层是什么事件类型），**不按分类名**——完整矩阵见 **R4.6**。

- **已被遮蔽的原始节点 / 旧替换体**：不显示「编辑」与「应用到会话」，显示徽章 `已被 #K 接替` + title：
  「这一条已经不在模型可见内容里了。想看它原来的样子或退回某一版，用 **版本历史**；要补一句更正，用「批注」。」
- **当前可见的替换体**：**仍然显示「编辑」**（可以继续改，`docs/01` F7）——不要因为"改过一次"就把整条链锁死。
- **`assistant/message` 行**：不显示「编辑」，显示徽章 `助手消息仅可批注` + title：
  「助手消息在平台上无法改写（两条规则互斥，`docs/01` F7.2）。要纠正它请用「批注」；要重建上下文，用「快照 + 子会话」。」
- 会话不在本进程：整列动作条禁用 + 顶部说明条（R4.4）。
- 轮次未闭合：写入类动作**不出现**（不是禁用后点了报错），并在顶部说明条写原因。
- 系统提示词 / 工具定义行：无动作条，且**不渲染空的动作区**（不留占位）。

### R2.4 「固定块（不变量）」面板（注入类的钉子）

- **位置**：右列，**上下文浏览器下方、快照与子会话上方**，独立一张卡片。
- **为什么需要它**：注入内容每轮被宿主重新注入 → 改一轮漂一轮。只给「编辑」而不给"钉住 + 比对"，
  下一轮就无从知道"我当初钉的那句话还在不在"（`docs/00` G4 / S4）。
- 列表每行：`块 id` · 状态徽章（**在效 / 漂移 / 已退休**）· `标签 · 版本 · 作用域（workspace 级：新会话也看得见）` ·
  **漂移结论**；行下：正文逐字预览 + `重注入` + `退休`。
- **漂移检查只做「逐字包含」判断**（不含推断、不含模糊匹配、不做相似度）：
  | 情况 | 结论文案 |
  |---|---|
  | 逐字出现在**当前这一步**的注入内容里 | `在效 · 逐字命中 #seq（名字）` |
  | 找不到，且这一步的注入被改写过 | `漂移 · 这一步的注入被改写过（#N），钉住的原文已不在里面` |
  | 找不到，也没被改写过 | `漂移 · 当前这一步的注入内容里找不到这段正文` |
  | 已退休 | `已退休：不再生效（历史版本保留）` |
- 两个动作都要先过 **R4.3 的确认框**：
  - `重注入`：短警示「会往会话追加一条消息，不可撤销。」+ 本次清单（固定块与版本 / **正文逐字** / 为什么现在注入）；确认后**逐字**追加，插件不改一个字。
  - `退休`：短警示「退休后它不再生效，但历史版本会保留。」+ 清单（块 id 与版本 / 当前生效范围 / 退休影响面）。
- 一块固定块都没有时，快照卡给出 R5.2 的建议（`建议先把目标 / 约束…存为固定块`）。

### R2.5 「高级编辑」开关（常用 / 高级 两档）

> 用户 2026-10-01 提议：技能注入 / 助手消息 / 工具结果 一般用户用不到，做成"高级编辑"。

- ⚠️ **划分依据不是"会不会漂移"**。漂移只跟一件事有关：**这条内容下一轮会不会被宿主重新注入** ——
  注入内容 ✅、**技能注入 ✅** 会漂（同族）；用户消息 / 助手消息 / 工具结果都是日志里的历史，**改了就定了、不漂**。
  真正的依据是**"用户需要动手的概率"**：
  | 档 | 哪几类 | 为什么 |
  |---|---|---|
  | **常用（始终可见）** | 用户消息 · 注入内容 · **技能注入** | 都是「**我告诉模型什么**」；消息说错了必须改，后两类每轮被重新注入（会漂、要钉住） |
  | **高级（默认收起「编辑」入口）** | **工具结果**（一轮几十条、「要动手」的概率低） · **助手消息**（平台本来就不给「编辑」，只有「批注」） | 都是「**模型 / 工具回了什么**」；数量最多、需要改的概率最低 —— 这正是「看着被吓到、按钮把常用动作淹掉」的来源 |
- **只收起「编辑」入口**：`批注` 在任何档位都保留（助手消息只能靠批注纠正，见 R2.1）；
  `存为不变量` 只属于注入内容与技能注入，两者都在常用档，不受影响。
- **不许凭空消失**（R2.3）：收起时该位置显示 `高级编辑` 小标记，title 写明「打开顶部高级编辑开关即可看到」。
- 开关**默认关**；它只影响按钮可见性，不改任何数据。

## 3. 行下内联编辑器

### R3.1 形态
**在那一行下面展开**，不弹窗（弹窗会盖住上下文，而用户要对照着上下文改）。同一时刻只有一个编辑器。

### R3.2 字段按内容类型决定（kind-aware）
编辑器字段由**底层事件类型**（宿主给的 `type`）与分类**共同**决定：

| 底层类型 | 编辑器字段 |
|---|---|
| `user/message`（含"注入内容""技能注入"里底层是 user 的） | **正文**（必填）+ 思考文本（可选，折叠在"高级"里） |
| `tool/result` | 结果文本 + `isError` 开关 |

> **批注只针对「你点的那一条」**（用户 2026-10-01 两次反馈后的最终口径）：
> - 目标必须用**人话**说清楚：`第 N 轮 · 第 M 步 · 类别` + **正文开头**，`#seq` 只退居括号里并注明"写进更正消息里供追溯，你不用记它"。
>   **不许**把裸 `#seq` 当成「是哪一条」的身份（用户：「`就这一条（#1240）` 我还是不知道这一条指的是哪一条」）。
>   **不许**让用户输数字（用户：「你还是要输入准确的数字，用户怎么能知道准确的数字？」）。
> - **不提供"从这一条到…"的范围选择器**（曾是选择器，已删）：一步里可能几百条、整个会话上万条，
>   既没有语义（「到后面」对一条*更正*意味着什么？），又是性能与体验负担 —— 用户的原话：「给这个选择反而会带来很多问题」。
> - 要作废更大的范围，**由用户写在「理由」里**（例如「上面第 3、4 条都作废」）—— 模型读的正是理由；
>   结构化头部里的 `seq` 只服务于我们自己的追溯与「已查看」记账。
| `assistant/message` | **没有编辑器**（只给批注；见 R2.1） |

> 早期那次尝试 的编辑器对五种类型显示**同一套字段**（连用户消息都给"思考文本"），实现时必须先按类型选字段。
> **用户消息 / 注入内容的主字段就叫「正文」**（不叫"可见文本"），并写明"模型看到的就是这一段"；
> **思考文本必须折叠在「高级」里**（`<details>`，默认收起）—— 用户 2026-10-01 实测问过"用户的消息不就一条吗？为什么是两条"。
> 界面上不解释"思考文本是什么"是错的——它是模型可见的 reasoning 块。

### R3.2.1 改第二次与回滚（这是**平台支持**的能力，不是绕过）
「编辑」只针对**当前可见的那一条**。所以：
- 改完一次之后，**同一条还在那里**（现在是替换体），可以**再改**；
- 想看/退回旧版本 → 用 **R4.5 版本历史**；
- **被遮蔽的原始行**永远不能再直接当目标（平台会拒，别给按钮）。

### R3.3 两步语义必须在编辑器里写明（不许含糊）
- 面板顶部一行说明，随动作不同而不同：
  - 编辑：`这一步只存本地草稿（不进会话）。要生效，提交后还需点「应用到会话」。`
  - 批注：`提交会立刻往会话追加一条更正消息，不可撤销；原文不会被遮蔽，模型两者都看到。`
  - 固定块：`逐字保存：插件不生成、不润色、不压缩。正文一个字都不会被改。`
- 提交按钮文案：编辑 = `保存草稿`；批注 = `提交更正到会话`；固定块 = `保存为固定块`。
  - 并且**在提交按钮旁边**把两步流程写成一行（用户 2026-10-01："点了『保存草稿』之后会产生什么结果？后面需要如何去做？"）：
    `第 1 步 保存草稿 → 只存在插件本地（模型还看不到）· 第 2 步 行上出现「未生效」→ 点「应用到会话」才会真的生效`。

**R3.3.1 提交按钮与确认框的关系（硬性）**
- **凡写入型提交按钮**（`提交更正到会话` / `保存为固定块` / `保存并应用` / `重注入` / `恢复这一版` / `打断`）：
  点击 → **先展示 R4.3 的确认框**（短警示 + 本次清单）→ 确认后才发 RPC → 取消则**什么都不发生**。
- **唯一例外**：`保存草稿`（不写会话、可一键放弃）→ 直接保存。
- 按钮文案本身**不等于**确认：`提交更正到会话` 只是入口，真正的授权发生在确认框里。

### R3.4 正文来源必须是全文（**硬性**）
- 预填的正文来自 `node.read`（宿主全文），**不得**把列表行上的 80 字预览塞进编辑器。
- 多段文本会被合并为一段 → 编辑器上方常驻一行灰字：`这条消息有多个文本段落；改写后会合并为一段。`（仅在原消息确实是多段时出现）
  > demo 里有一条 **213 字 / 4 段**的演示消息 `#1305`（最后一轮的最后一条用户消息，也就是 R1.4 按钮的目标）：
  > 点一下就能看到"列表里是 90 字的截断预览、编辑器里是 213 字全文"这个差别（截图 `demo/screenshots/r34-fulltext-multipara.png`）。

### R3.5 键盘与失败
- `Esc` = 关闭编辑器（**不丢已保存的草稿**；未保存的输入按 R3.6 询问）。
- `Cmd/Ctrl + Enter` = 提交。
- 提交失败：**不清空输入**，就地显示宿主原文，可重试。

### R3.6 关闭时的未保存保护
- 编辑器有未保存输入且用户按 `Esc`/点取消 → 就地提示一次：`有未保存的输入，关闭会丢失。`（不做全局弹窗；提示就长在编辑器底部，点第二次关闭即生效）

## 4. 全局状态与回执

### R4.1 「还有 N 条未生效」常驻
- 位置：右侧浏览器卡片顶部（吸顶）。
- 内容：`还有 N 条改动未生效` + 一个 `全部应用` 次级动作（逐个列出要改的 seq，点击后二次确认，**逐条提交**，不做批量静默提交）。
- 列表很长时也要能看到（吸顶，不随滚动消失）。

### R4.2 改动的可见状态
| 状态 | 行上的表现 |
|---|---|
| 只有草稿 | `未生效` 徽章 + 可点 `应用到会话` |
| 已生效 | `原 #N → 新 #M`（`M` 可点，跳到新事件所在行） |
| 已生效又被遮蔽 | `原 #N → #M（#M 已被后续替换遮蔽）` |
| **已回滚** | `原 #N → #M → 回滚 #K`（每一步都能点开看内容） |

### R4.3 写入类动作的确认（短警示 + **本次清单**）

**总规则**：凡会**写会话 / 建会话 / 改变运行中的子会话 / 写持久数据**的动作，点击后**先出确认框**。
确认框 = **短警示**（下表逐字给出）+ **本次清单**（这一次操作的**具体值**——只说"会写会话"不算实现，必须让人核对到内容）。
**唯一的例外**：`保存草稿` 不需要确认（它不写会话、且可一键放弃）。

| 动作 | 短警示（逐字，评审可改） | 本次清单必须逐项列出 |
|---|---|---|
| 应用到会话（apply） | `会向会话追加一条替换记录，之后无法删除；原文对模型永久不可见，但仍保留在日志里。当前可见的那一条之后还能继续改，也能从版本历史里恢复某一版。` | 目标 `#seq`（当前可见节点）· **原文全文**（可展开）· **改后全文** · 理由 |
| 批注（annotate） | `会向会话追加一条消息，不可撤销；原文保留，模型两者都能看到。` | 更正目标 `#seq` · 作废范围 · 理由 |
| 重注入固定块 | `会往会话追加一条消息，不可撤销。` | 固定块标签与版本 · **正文逐字**（可展开）· 为什么现在注入 |
| 回滚到某一版 | `会向会话追加一条替换记录，把模型看到的内容恢复成你选的那一版。原文与中间版本都还在日志里，之后还可以再改。` | 当前可见目标 `#seq` · 要恢复到的 `#toSeq` 及其**正文**（可展开）· 理由 |
| 存为固定块 | `会把这段正文逐字保存为固定块（workspace 级：本数据目录下所有会话都能看到它）。插件不生成、不润色、不压缩。` | 标签 · 正文逐字 · 作用域 |
| 退休固定块 | `退休后它不再生效，但历史版本会保留。` | 块 id 与版本 · 当前生效范围 · 退休影响面 |
| 冻结快照 | `只在本插件本地记录切点、计数、时间、备注与固定块版本，不写会话。` | 切点 `cutSeq` · 条目数 · **人写备注**（插件**不生成摘要**，见 `docs/00` N4） |
| 开子会话 | `会用这个会话「已完成的轮次」做种子新建一个会话（种子是一次性的：之后本会话的新轮次不会进去）。` | 五项见 `docs/06` §4.1（切点 / 人写首条任务 / 继承与不继承 / 副作用 / 取消语义） |
| 压缩子会话 | `子会话的历史会被摘要取代，不可逆。失败也通常会留下痕迹。` | 目标 `childId` · 将被替代的区间与条目数 · 不可逆提示 |
| ~~派活（`child.send`）~~ | **不做**（**Q12=A，用户已定**）：派活/任务板/成员导航属于**官方 Agent Teams**。要继续跟这个子会话说话，请在**官方子会话视图**里用它自己的输入框（那里的输入与会话是一体的，见 R5.1.1） | — |
| **打断子会话（interrupt）** | `会向子会话 #ID 发出取消信号；未完成的工作可能被中断，不可撤销。` | 目标 · **当前状态**（running/idle）· 发出的信号是什么 · "已提交的工作不会被回滚"这句实话 |
| 放弃未应用的改动 | `只清本地草稿，不影响会话；未保存的输入会丢失。` | 将丢弃的草稿条数与 `#seq` 列表 |

### R4.4 会话未结束 / 会话不在本进程
右侧卡片顶部一条**常驻说明条**（提示样式，不是 error 样式）：
- 轮次未结束：`当前轮次还没结束 —— 改动只能在轮次边界提交。`
- 会话不在本进程：`这个会话不在本进程里，只能查看，不能编辑。`
- 说明条里带一个 `刷新`（重新问宿主要 `turnState`）。

### R4.5 版本历史与回滚（G9 / S8）

**入口**：每条**被改过**的行（`原 #N → …` 链上的行）给一个 `版本历史`，展开后按时间列出这条消息的全部版本：
`#A 原始（2026-09-28 16:02）` / `#M 第 1 次改写（16:20）` / `#K 回滚（16:31）`；每版可**就地预览正文**（不跳页）。

**恢复条件（必须按状态给按钮，不许给了再报错）**

| 状态 | 历史可预览 | 可恢复 | 界面上怎么说 |
|---|---|---|---|
| 普通（未压缩、本会话、`#toSeq` 正文可读） | ✅ | ✅ | `恢复这一版` + 二次确认（R4.3） |
| **`#toSeq` 落在压缩 checkpoint 之前**（`docs/01` V7/V9 未通过前） | ⚠️ 视 V8 结果 | ❌ | `这一版在压缩之前，目前不能恢复（历史正文读取能力尚未验证）。` |

## 5. 快照 / 子会话面板（M5）

### R5.1 位置与内容
放在右侧浏览器卡片**下方**（同一列），标题「快照与子会话」。内容：

1. **冻结（幂等）**：`冻结当前位置`（+ **人写备注**输入框，插件不生成摘要）。一条记录的**身份** = 「切点（最后一个 `turn/end`）+ 当时在效的固定块版本」。
  - 同一身份**再点不新增记录**，而是弹「这一刻已经冻过了」并问要不要**更新备注**（用户 2026-10-01：
    "同一位置再点一次为什么会出现多条？我没理解"——重复记录是废记录）。
  - **备注可改**（那是你写的话，写错了就地改，不必删了重冻）；**切点 / 条目数 / 冻结时刻 / 当时的固定块版本不可改**
    （客观读数，改了就不叫凭证），只能删（删除要确认）。
  - 记录行上给 `改备注` 与 `删除` 两个次级动作；列表按时间倒序（显示 `第 N 轮末 · 条数 · 时间 · 固定块版本 · 人写备注`）。

2. **分叉起点 = 每条冻结记录自己的「从这里开子会话」（用户 2026-10-01 定的结构）**：
   > 用户原话：「我应该在我冻结的那一条后边加上开子会话，而不是在子会话跟冻结当前位置是同一条。」

   - **每条冻结记录行上直接放主按钮 `从这里开子会话`**，后面才是 `改备注` / `删除`；
     「想在哪一刻分叉」由**你在哪一行点**回答 —— **不设**全局的「开子会话」按钮、**不设**"从这一刻分叉"下拉
     （下拉是把同一件事拆到别处再问一遍，用户会问「那我到底在哪一条上分叉」）。
   - 行上写清这一条作为种子的客观字段：`种子 = 这一条（第 N 轮末 · 条数 · 固定块版本 X）`。
   - **没有冻结记录时**：不出现任何开子会话入口，只提示第一步 —— 「先点 `冻结当前位置`」
     （冻结 → 在那一条上开子会话，是**两步**，而且第二步长在第一步的产物上）。
   - `冻结当前位置` 按钮旁常驻一句指引：`冻完会在下面多出一条记录 —— 开子会话就在那条记录上点`。
   - `seedOf` 之类的实现只接受**一条真实存在的记录**：记录被删掉后再点，必须**拒绝建会话**，
     不许"拿最新那条顶上"（否则用户以为从 A 分叉，实际从 B）。
   > **冻结记录不是书签，而是"一个出发点"** —— 它的三条客观字段就是**种子参数**：
   > **切点**（从哪个 `turn/end` 之后的日志做种子）、**条目数**（当时的规模）、**当时的固定块版本**（当时在生效的口径）。
   > **多条的意义**：时间在往前走，你会在**不同时刻分叉**。例如昨晚口径 v1 冻一条、今天改了口径 v2 再冻一条；
   > 现在要补一个"**仍按 v1 干**"的子会话（那批活的验收标准是 v1），就选**早的那条**当起点 ——
   > 只有一条记录时这件事做不到（只能"从现在分叉"）。
   > **为什么参数不可改**：改了就等于声称"这个子会话是从某个你从没冻结过的时刻分出来的"（伪造凭证）。
   > 备注是给你看的 → 可改；三参数是给种子用的 → 只读，不想要就整条删。
   > **还没有冻结记录时**：开子会话会**自动补记一条**，记录上标明"（开子会话时自动记录）"——
   > 这样每一次分叉都有凭证，用户不必先手动冻一次。
3. **开子会话**：选好起点 → 填**首条任务**（必填，人写）→ **确认框（`docs/06` §4.1 五项）**（第 ① 项就是所选起点的客观字段）→ 确认后才建。
4. **子会话索引**（**不是会话树**——理由见 R5.1.1）。每行**来自平台的投影**（`subagentCatalog` + `subagentTiming`，我们**不自建** children 表）：
   `#004c37a5 · 可续接 · 运行中 3 分 12 秒 · ≈12k tokens · 来自快照 snap-…161449`
   **来源徽章（必须）**：官方 Agent Teams 的 teammate **也是可续接子会话、也会进同一个 `subagentCatalog`**（`docs/01` F28）。
   所以每行要标明来源：`本项目发起`（能对上我们 `snapshot_links` 的）或 `来自 Agent Teams`（对不上的）。
   **对不上的那些**：不做我们的压缩/打断动作，只给 `打开`（跳官方视图）与提示 `这类成员请在会话页头的 Agent Teams 面板里管理。`
   ——**不隐藏、不假装不存在，也不重复实现官方的协作层**（消息 / 任务板 / 成员导航，`docs/01` F30）。
   行尾动作（**对 `本项目发起` 的成员**，依据 `docs/06` §3.2 的 A′）：
   - `打开` → **跳到官方视图**（父会话页头的血缘目录，或右侧 Sidebar 里的那个子会话对话）——**我们不在面板里重画对话**；
   - **`派活`（经官方）** → 先开确认框（R4.3），确认后调 **`ctx.agentTeams.sendMessage(lead, {target: <名册名>, content})`**
     —— **走官方通道**，我们不实现自己的投递；返回 `accepted`/`queued` 要如实显示（queued 不许重发）；
   - **`建成官方任务`**（可选动作）→ 把这条待办写成官方任务 `createTask({subject, description, blockedBy?, writeScopes?})`，
     写成功后在**官方任务板**上就能看到（我们显示的是同一份数据）；
   - `压缩` → 先体检（R5.3）；
   - `打断` → 先开确认框（R4.3）；**团队成员**走 `ctx.agentTeams.interrupt(lead, targetName)`，**裸子会话**走 `subagents.interruptByParent`。
   **来源徽章**用 `tryMembership(agent)` 判定（`本项目发起` / `Agent Teams 成员`），**不按 label 猜**。
   **团队不可用时（`ctx.agentTeams` 不存在）**：`派活`/`建成官方任务`/团队成员式`打断` 全部**不出现**（不是报错），
   只留 `打开` / `压缩` / 裸子会话`打断`，并说明"本机未启用官方智能体团队"。
   顶部一行容量提示：`活跃子会话 2 / 8`（`maxActiveSubagents` 默认 8；触顶时给人话"等某个结束，或先关掉一个"）。
   ⚠️ **官方团队的 teammate 也占同一份额度**——两个数要合起来看（`docs/06` §3.2）。
   **官方团队区块（只读，直接显示官方那份数据）**：任务板与 roster **读 `agentTeam` 投影**（客户端 seat，与官方面板同一份、
   实时更新），**不复制、不缓存、不自己算依赖就绪**；投影报 `failure` 时，按官方做法**在最后有效数据之上显示该失败**。
   区块里给一个 `去官方面板` 的跳转（成员导航复用官方）。
4. **待处理的结果**（这条直接对应"主会话怎么接着干"，但要**分三个状态**，不许合并成一句"已继续"）：

   | 状态 | 判据 | 文案 | 动作 |
   |---|---|---|---|
   | **已收到平台结算通知** | 父会话日志里出现了 `subagent-settled` 通知（键 = `(父会话, 该通知的 seq)`） | `子会话 #004c37a5 已结束：<一句话结论>` | `去看结果`（跳到那条通知）· `已查看`（写本地 `pending_results`） |
   | **父会话下一轮已开始** | 父会话里出现**可关联的后续 `turn/start`**（不是"我们猜"） | `父会话已开始处理这件事` | — |
   | **回流未确认** | 没有结算通知（例如父 Agent 当时不在进程 → 平台**不投递**） | `没收到平台的结算通知 —— 子会话结束了，但父会话没收到回流。` | `让主会话接着做`（人工把结果交回）· `去子会话看结果` |

   **只有拿到第三条判据才敢说"已继续"**；`docs/01` F12.1 的投递是**尽力而为**，界面不许越界承诺。
   未处理项的定义、`已查看` 记在哪、重启后怎么从父日志重建：见 `docs/06` §6 第 6 条的表格。
5. **下一步该做什么**：把 `plan.next` 的结论显示成一句话 + 一个动作按钮（`reason` 必须显示，**不许让用户猜**）。

> **"派活"与"打断"都是写入类动作**，因此和 `apply` 同级：**没有确认框就不算实现**（`docs/06` §4 的 A8/A10）。

> ⚠️ **子会话自己的工具审批不继承父会话**（`docs/01` F12.1 末段）：它可能在"等待用户授权"处停住。
> 面板必须把 `等待授权 / 未知阻塞` 与 `运行中` **分开显示**，并给 `去官方子会话视图处理` 的跳转；
> **我们绝不代替它审批**（插件直调绕过的是**我们**发起的动作的审批，不是子会话里模型调工具的审批）。

### R5.1.1 为什么**不**在左侧会话列表里嵌子会话（这是官方行为，不是偷懒）

官方 UI 包 `dsh-client-ui-subagent`（已随运行时挂载）在自己的 README 里写着：
**"普通会话侧边栏会省略 subagent 对话，因此父会话页头目录是它们的导航入口。"**
它的做法：父会话页头的标题当**谱系面包屑**，操作区放**后代数量触发器**（悬停 150ms 打开目录树、按需加载任意深度），
点一个后代就以确切地址打开它的对话（空间允许时优先在**右侧 Sidebar** 独立分栏），
行上显示 mode / 活动状态 / title / token / 活跃轮次耗时；**可续接**子会话在那里还有普通输入区和独立 **Stop**。

**所以我们的设计是**：
- **不重画会话树、不在左侧列表嵌套子会话、不在面板里复制一个对话视图**；
- 我们的「快照与子会话」面板 = **父会话视角的索引 + 动作 + 跳转**（索引看"有什么待处理"，跳转看全文）；
- 好处：① 不和官方 UI 打架；② 用户用的是官方那个功能完整的视图；③ 我们不必维护会话树的一致性。

### R5.1.3 子会话的上下文也能编辑吗？（能 —— 但必须"打开它"，且要在它空闲时）

> 用户 2026-10-01 问：主会话负责收集汇总、子会话干重活（一个子会话可能跑上千轮），
> 这种情况创建子会话之后，"子会话可以对上下文进行编辑吗"？——他说在官方智能体团队模式下
> **看不到子会话的上下文**，所以怀疑改不了。

- **能编辑，关键动作是「打开它」**：子会话是**真会话**（独立 `sessionId`、独立日志、持久化，`docs/01` §F13）。
  我们的面板挂在**会话视图**上，永远显示"**当前标签页选中的那个会话**" ⟹
  用官方谱系目录（父会话页头）或右侧 Sidebar 打开子会话后，面板就切到**它的**上下文，
  编辑能力与父会话**完全一样**（改条目 / 批注 / 存为不变量 / 冻结 / 压缩）。**不需要两套界面。**
- **为什么"在父会话里看不到、也改不了它"是正常的**：`apply` / `annotate` 要求目标是**该会话自己的 live Agent**
  （`docs/01` §"会话不 live 时对接点全不可用"）；官方 Agent Teams 面板只提供**成员导航 + 只读任务板**（`docs/01` F30），
  它本来就不承担"编辑另一个会话的上下文"。所以我们不做"跨会话就地改"，只做**跳过去、在它自己的视图里改**。
- **两条前提**（都必须在界面上如实说出来，不许等用户点了才发现）：
  | 前提 | 拿不到时 | 界面怎么说 |
  |---|---|---|
  | **轮次闭合** | 子会话正在跑（几乎总在跑）→ 写入类动作**不出现** | `运行中：打开它 = 面板切到它的上下文；轮次闭合前只能看，不能改（要改就先等它空闲或打断）` |
  | **在本进程** | `ctx.agents.get(sessionId)` 拿不到 → 只能只读 | `这个子会话当前不在进程里，只能查看。`（口径同 R4.4） |
- **给这种用法的建议流程**：要改子会话 → **趁它空闲**（或先 `打断`）→ 打开它 → 改 → 让它继续。
  "跑上千轮的长子会话"本身没有错，但**改它的窗口只在轮次之间**。

### R5.1.1.1 为什么不把子会话"缩进嵌进左侧会话列表"（用户 2026-10-01 问）

用户看到微信群里有人这样做过：「在左侧工作区下的当前会话下面加一个真 session 子会话，缩进两行，看着像层级」。
核实结论（`docs/01` F36）：**那不是官方 DSH 的默认界面，插件也做不到** ——

- 官方两处明写：会话侧边栏**隐藏/省略** subagent 来源的会话；子会话的导航入口是**父会话页头目录 + 右侧 Sidebar**。
- 插件在会话行上**能**占的插槽只有 action 类（行菜单项、行尾悬停按钮、行首标记、悬浮卡片），**没有"插入新行"的插槽**。
- 我们**不重复造**：继续沿用官方入口；跳到子会话后，本插件的面板会跟着切过去（R5.1.3）。
  若以后确实需要「左侧可见」，那是**上游产品建议**（新插槽），不是本插件能实现的能力。

**能力上没有缺口**：用户描述的「主会话开子任务 → 子会话执行 → 完成后通知主会话 → 主会话接着干」，
DSH 本来就支持，而且是官方推荐形态（可续接子会话 + 结算通知回流，`docs/06` §2/§3）。

### R5.1.4 「发消息」= 会话之间互通（子会话是**多轮**的）

- **子会话行上给一个 `发消息`**（`own` 来源的裸可续接子会话）：写一句话 → 成为**它的一个新轮次**。
  - 走的是**官方子会话通道** `ctx.subagents.prompt({delivery:"queue"})`；`steer` 则插到最近的步骤边界。
  - 它忙就排队、空闲就立刻起一轮、**不在进程里会冷恢复**（容量满 → `subagent/delivery-unavailable` 翻成人话）。
  - **不依赖官方团队**：团队关着也在（这是子会话自己的能力）。
- **团队成员的「派活」是另一条**（`agentTeams.sendMessage`，团队专用）：**团队不可用时它不出现**（不是置灰，R5.1）。
  两者不许共用同一个 `data-act`（本轮就踩过：把"发消息"接成了 `csend`，与"派活"撞名，被护栏抓住）。
- **开子会话时可选**：单独的 `provider / model / reasoningEffort`（`agentOptions`）与短 `label`

### R5.1.4 「发消息」= 会话之间互通（子会话是**多轮**的）

### R6.4 移动端适配（**设计进去，不是断点堆出来**）

参照参考插件：主布局**没有一处 `@media`**，靠的是流式与容器查询。

- **V9 流式列**：两列用 `flex: 1 1 min(420px, 100%)` + `flex-wrap: wrap` → 窄屏自动单列，宽屏自然两列。
- **V10 卡片内自适应用容器查询**：卡片 `container-type: inline-size`，内部用 `@container (max-width: …)` 改排布。
- **V11 真触屏才放大**：`@media (pointer: coarse)` 下把可点区域提到 **≥44px** —— 用 pointer 判断，**不要**用窗口宽度（桌面窄窗口不是触屏）。
- **V12 横向滚动条**：统一 `overscroll-behavior-x: contain` + `-webkit-overflow-scrolling: touch` + `touch-action: pan-x`，
  并由 JS 兜 WebKit 的横向 wheel（见 R1.9）——**滑到头不许把整页带走**。
- **V13 安全区**：底栏/抽屉/弹窗用 `env(safe-area-inset-bottom)`，顶栏用 `safe-area-inset-top`（iPhone 手势条与刘海）。
- **V14 页面不横向滚**：`body { overflow-x: hidden }`；横向滚动只发生在卡片内部的滚动条里。
- **V15 iOS 字号不放大**：`-webkit-text-size-adjust: 100%`。
- **V16 长文本不撑破**：错误码、正文、理由等一律 `overflow-wrap: anywhere`。

>
> **讲解模式的硬规矩（2026-10-01 由用户的实测反馈定下）**：讲解模式**只许加编号，不许改变被测元素自己的样子**。
> 1. 高亮**只能画在伪元素（`::after`）上**，不得给元素自身设 `outline`/`background`/`border` ——
>    否则 `body.explain [data-explain]` 的特异性（0,2,1）会盖掉元素自己的状态样式。
>    实测事故：开着讲解模式时趋势柱体的 hover 与「选中」整片失效，所有柱子长得一模一样（用户因此以为柱体没有 hover/选中反馈）。
> 2. 高亮**跟着编号走**：只有真正挂了编号的元素才被标亮（否则趋势图里几十根柱子会各自带一个虚线框，图表就不像原样了）。
> 3. **同类重复元素只标一个编号**：趋势柱体只标**当前选中的那根**、轮次刻度只标第一格，其余行为相同、不重复标。
> 4. **编号连续、且顺序由"元素类别"决定**（＝按讲解词典的先后排，再依次编 1..N），
>    **不按出现顺序现数**：按出现顺序数的话，切换按轮次/按步骤时前面的元素个数会变
>    （步骤模式多一个 ✂ 标记、轮次模式没有刻度格的 `data-explain`），实测"点轮次时第 1 步是 18、点按步骤时变成 20"。
>    也不直接用词典序号当编号 —— 那会留下空号（实测缺 9/13/16/17/22/23/25，用户问"这些在哪里"）。
>    两者兼顾后：**编号 1..N 连续**，且切换粒度时柱子的编号不变。
> 5. 讲解模式**不占用**元素的点按：序号是独立节点，只吃掉自己那次点击（见 `docs/10` M05-22）。
> 6. 编号节点必须挂在**能装子节点**的元素上：`select` / `input` / `textarea` / `img` 装不下 `<span>`，
>    塞进去会被浏览器直接丢掉 → 那类元素要**外面包一层**（本插件里是 `.pickwrap`）再把 `data-explain` 挂到包层。
>    实测事故：步骤下拉的编号 11 一直"看不见"（用户问"11 编号在哪里？"）。
> 自动化护栏：`demo/check-static.mjs` 的第 4/5/7/8 条契约 + `demo/check-runtime.mjs` 的讲解模式/主题用例组。
>
> **自检工具的位置**：「自测面板」（自报元素尺寸、横向溢出、趋势柱数与刻度）是**验证工具**，不是给用户的功能，
