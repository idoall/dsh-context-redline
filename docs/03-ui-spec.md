## 1. 左侧：轮次 → 右侧（本插件最大的一处 UI 增量）

### R1.1 轮次选择驱动右侧
点趋势图的**轮次条/某一步的柱子**，或用右侧浏览器标题里的两个选择器 → 右侧浏览器切到**该轮末步 / 该步**。
- 一个轮次有多个 step，**没有"轮次本身的 surface"**这个实体（平台事实：`SurfaceNode` 只有 `seq` 没有 `turn`）。所以规则写死为：**轮 → 该轮最后一个 step**，并在标题里**说出来**。
- 标题格式：`第 25 轮（共 1 步，显示末步）`。
- **不得**复用上游的 `pinSeq` prop 来实现（上游每次 `pinSeq` 变化会重置手风琴展开状态）；要新增一个独立的 `turnSel` 语义。

### R1.1.1 ⚠️ 刻度带必须与柱体**逐列对齐**（用户 2026-10-02 报"错位"）

**问题**：轮号刻度带与上面的柱体错位，越往右偏得越多（实测：柱体列距 17px、刻度带 20px ⟹ 第 28 格偏 81px）。

**参考实现（`dsh-context`，源码 `~/.dsh/profiles/web/node_modules/dsh-context/lib/client.js`）**：
柱体行与轮号行是**同一个滚动容器里的两行 flex**，两行用**完全相同的 `gap` 与左右 `padding`**：

```css
.lc-chart { display:flex; align-items:flex-end; gap:2px; width:max-content; min-width:100%; padding:18px 2px 0 }
.lc-bar   { width:14px; flex:none }
.lc-turns { display:flex; gap:2px; width:max-content; min-width:100%; padding:0 2px; margin-top:4px }
```

⟹ **每一格的宽度只算"它覆盖的那几根柱子 + 它们之间的 gap"，不含尾随 gap**：

```text
跨度 k 根柱子： spanW(k) = k*BAR_W + (k-1)*BAR_GAP
整条内容宽：   chartW(n) = spanW(n) = n*BAR_W + (n-1)*BAR_GAP
```

**曾经的错误写法**：格宽 = `k*(BAR_W+BAR_GAP)`，而容器又有一条 `gap` ⟹ 每格多算 1 个 gap。
**不变量（已加护栏，`demo/check-runtime.mjs`）**：① 按轮次：每格宽 = `spanW(1)` 且格数 = 柱数；
② 按步骤：每格宽 = `spanW(turnSteps(t))`；③ 所有格之和 + 格间 gap = `chartW(柱数)` = 内层宽度。
浏览器实测（边界级）见 [`demo/screenshots/measure-log.md`](demo/screenshots/measure-log.md) §22：两模式下每格边界与其覆盖的首/末柱体边界误差 ≤0.6px。

### R1.1.2 趋势图下方的「选中态状态行」（照参考插件 `RequestDetail` 抄，用户 2026-10-02）

**它是什么**：趋势卡最下方**一行**，说清"你现在看的是哪一根柱子"；点柱子 / 切粒度 / 切模式时它跟着变（**横向滚动时它不动**）。

**逐条照参考插件**（`dsh-context` 的 `src/client/components/requestDetail.tsx` 头行 `.lc-detail-head`）：

| 情形 | 显示 |
|---|---|
| **按轮次**且该轮**多步**（轮聚合柱 = 该轮**最后一步**） | `第 t 轮 · 共 n 步` + 标签 **`末步`** |
| 其余（单步轮 / 按步骤） | `第 t 轮 · 第 s 步（共 n 步）` |
| 该柱带着压缩 / 裁剪事件 | 追加 **`✂ 第 t 轮 · 第 s-1→s 步`**（事件发生在两根柱子**之间**；`title` 给出事件正文） |
| 时间 | `HH:MM`（当前那一步再加「· 当前（下一次请求）」） |
| **总计**模式的指标 | 参考插件用 provider 的真实字段（`实际 prompt` / `输出 output` / `缓存 cacheRead%`）；**demo 没有这几个字段** ⟹ 用**估算合计 ≈ …** + **N 条** + **前三个类别**代替（不编不存在的数字） |
| **增量**模式 | 换成单个带正负色的 **`Δ ±net`**（与上一根柱子比），不再给合计 |

**为什么位置也要抄**：参考插件把它放在 `<TrendChart>` **正下方、滚动容器之外**；所以横向滚动图表时，状态行保持不动 —— 这条已写成护栏（⑥）。

**「点轮号条」的行为也照抄**（参考插件 `onPickTurn`，用户 2026-10-02 确认「改」）：
`setGranularity('turn') + setFocusTurn(turn)` ⟹ **点刻度带的一格 = 切到「按轮次」粒度 + 把这一轮的柱子居中**（一次性），
**不改当前选择** —— 它与「点柱子 = 选中那一步」是两件不同的事。两端的轮会被 clamp（不能居中就贴边）。
⚠️ 实现坑（已修 + 已加护栏）：**两种粒度下格子属性不同** —— 按步骤模式用 `data-turn`，按轮次模式是 `list.map()` 出来的、只有 `data-seq`，
所以定位必须能"回退到按第几格找"，否则**静默失效**（找不到格子时现在会如实报「定位失败」，不再无声无息）。

### R1.1.3 趋势框「照上游做的」部分（用户 2026-10-02：「照抄它这一块区域就行」）

**范围**：**只动「上下文趋势」这一个框**，其它卡与右侧浏览器一行不动；**交互仍是我们的**（点柱子 → 右侧跟着换）。

| 项 | 照上游 `trendChart.tsx` / `trendChart.css` 的做法 | 我们的落地 |
|---|---|---|
| 卡内排布 | 左标题 + 右侧按钮组；聚焦/刻度是**一行短副标题** | 副标题 = `按轮次（共 28 轮） · 刻度 = 7.9k（自适应）`；原来那行 **~200 字长说明删掉**。⚠️ 用户 2026-10-02 后续又点名删掉两样：**标题旁的 `?`** 与 **`回到当前`** ⟹ 标题行只留 `按轮次 / 按步骤 · 总计 / 增量 · 自适应` 五个按钮（`EXPLAIN[trend.read]` 与 `EXPLAIN[trend.jump]` 一并删除） |
| 纵轴 | `.lc-axis-top/-q3/-mid/-q1/-bot`，位置 13/41/69/97/125；`.lc-grid` 虚线网格 + 实线零线 | 同上（**位置数值照抄**）；实测网格线相对柱区 = `0/28/56/84/112`，轴标签 = `-1/27/55/83/111`（同一套坐标，误差 ≤1px） |
| 轮号带 | `.lc-turns` 每格带**交替底色**（`TURN_FILLS`），hover 高亮 | `.tcell.alt` 交替底色（颜色走我们的令牌）；悬停加 `.turn-hover` |
| hover 联动 | `activeTurn = hoverTurn ?? 悬停柱子所在的轮`（**悬停轮号优先**，选中不参与） | 同一语义；纯 DOM 加类、不重画（否则 tip 会被重建掉） |
| 进入动画 | `.lc-bar-in`，`calc(var(--lc-i) * 15ms)` 逐根升起；切粒度/模式时播 | `--i` + `.tbar.enter`；**只在切粒度/模式/自适应时播**（点柱子/选中不重播，与上游一致） |

**颜色**：按用户 2026-10-02 的裁定 —— **结构/布局/交互照抄，颜色仍用我们的主题令牌**（`--dsw-alias-*` / `--ds-color-*`），不搬上游的原始色值。

### R1.2 轮级与步级并存
- 保留上游的步级下拉（`当前（下一次请求）` + 每个 step）。手动在下来里选一个 step = 退出轮级选择（标题变回 `第 T 轮 · 第 S 步 (共 N 步)`）。

### R1.3 左侧每轮显示"有多少内容注入"
- 轮次条/轮次列表上，每轮显示两个数字：**用户消息 N** 与 **注入内容 N**（同一套配色：用户消息 = 绿、注入内容 = 紫，与上游 `CATS` 一致）。
- 数字来自 `RequestRecord` 的分类 token 计数（上游已有）→ **不新增服务端查询**。
- 若空间不足（窄屏）：**只显示注入内容条数**（用户最关心的"漂了没有"信号），并在 title 里给全。

### R1.5 趋势图的**粒度开关**：按轮次 / 按步骤（默认按轮次）

- 按轮次：一轮一根柱（合并该轮各步，取**末步**；柱下方标该轮步数）。点柱子 = 选中这一轮（右侧显示该轮**末步**）。
- 按步骤：一次请求一根柱。点柱子 = 选中那一步。
- 标题必须把规模写出来：`按轮次（共 28 轮）` / `按步骤（共 72 次请求）` —— **用户要能一眼看出"有多少轮"，而不是只看到最后几轮**。
- 参照：参考插件 `trendChart` 的 `granularity: 'step' | 'turn'`。

### R1.6 趋势图的**模式开关**：总计 / 增量（默认总计）

- 总计 = 该次请求的上下文量；增量 = 比上一次请求多了多少。
- **增量可以为负**（压缩 / 裁剪之后上下文变小）：**围绕零线**画 —— 涨的段在零线**上方**、跌的段在**下方**，
  **颜色仍然是类别**（方向表示正负，不是"变红"）。不得把负值截断成 0。
  **零线位置按 `maxUp : maxDown` 成比例分割柱区**（照参考插件 `trendChart.tsx` 的原话：
  "the zero line splits the bar area PROPORTIONALLY to the larger side, so the px-per-token scale is
  identical above and below it"）—— 否则上下两截每像素代表的量不同，读起来会骗人。

### R1.7 **自适应刻度**（默认开）

- 打开：纵轴上限只按**当前可见的那几根柱**算；关闭：按整段历史算。
- 理由：长会话里远处的一个尖峰，会把眼前这些柱子全压成一条线。滚动时要跟着重算。

### R1.8 **聚焦某一类**

- 点分类树里某一类的色块 → 趋势图只画该类并重新缩放；标题显示 `聚焦：注入内容（全部）`，点"全部"恢复。
- 再点同一个色块 = 取消聚焦。

### R1.9 **固定柱宽 + 横向滚动**（不许"压缩到看不清"）

- 柱宽固定（14px），**不随轮数变窄**；柱多了就横向滚动。
- 横向滚动容器：`overscroll-behavior-x: contain`，并在 WebKit 上**取消**到边后的横向 wheel ——
  否则在手机上滑到趋势图边缘会触发"左滑返回"，把整个界面带走（参考插件 `overscroll.ts` 就是为这个）。
- 选中柱子被滚动到可视区内（居中）。⚠️ 用户 2026-10-02 点名删掉了 `回到当前`（趋势框里不再有这个按钮）。

### R1.10 **轮次分组刻度带**（两种模式都必须能点、且点完看得出选中）

- 柱子下面按轮分组的刻度带：**按步骤**模式每格宽度 = 该轮步数；**按轮次**模式每格按柱对齐；两种模式格内都标轮号。
- 点一格 = 切到「按轮次」粒度并把该轮居中，**不改当前选择**。两种模式都必须满足定位与提示契约（`docs/05` §2.7 之外的独立护栏在 `demo/check-runtime.mjs`）：
  1. 每格带 `data-explain="trend.strip"`（讲解模式要能覆盖它 —— 2026-10-02 前只有按步骤模式带）；
  2. **点后会定位到该轮**（选择本身不变）；
  3. **点一下弹人话提示**（`已切到按轮次，并定位到第 N 轮`）—— 2026-10-02 前按轮次模式传 `why=null`、**什么都不弹**，
     用户报「（那排轮号）17 点了没有反应」。
- **触屏**：`pointer: coarse` 下格子高度 ≥44px；但**宽度受坐标轴限制**（= 该轮长度，手机上一轮可能只有十几像素）
  ⇒ 必须给替代路径：标题栏的**轮下拉**（T 项，不随步数增长）—— 触摸时那排格子太窄点不准，用下拉选轮最稳。
- 按轮次模式下刻度带**仅作标号**、不承担"跳转导航"职责（保留下它的理由是它是**坐标轴**：它给出"这一根柱子是第几轮"，见 R1.1.1）。

### R1.11 **步级快捷片 + 顺序导航** —— ⛔ **已作废（用户 2026-10-01 决定）**

> **原文（保留备查）**：当前轮的每一步一片 `第 1 步 / 第 2 步 / …` + `当前（下一次请求）`；
> `◀ 上一轮 / 下一轮 ▶`、`◀ 上一步 / 下一步 ▶`；`←/→` 键等价于上一步/下一步。
>
> **为什么删**（用户原话）："这些没有太大意义，因为用户鼠标移上去了……移到柱体上自然就看到了，
> 点『上一步』『下一步』帮助不大。反而会给用户造成干扰。" ⟹ 柱子 hover 即报"第几轮 · 第几步"、
> 点一下即选中，那一排只是重复信息。
> **保留**：柱子下面那行**轮号刻度带**（R1.10）—— 它是图表的坐标轴，不是导航。
> **连带**：`←/→` 快捷键一并取消；步级选择仍然可以在**右侧的步骤下拉**（R1.13）里做。

### R1.12 **压缩 / 剪枝标记 ✂**（一个事件 = 一根柱，绝不重复）

- **一个事件只标在「它之后的第一个请求」那一根柱子上**（照参考插件 `attachMarkers`：找到第一个 `seq >= 事件 seq` 的请求就 `break`）。
  ⚠️ 不许"标在它之后的每一根柱子上" —— 那会让 2 个事件显示出 3 个剪刀（本插件实际踩过这个坑，冒烟测试现在锁死这一点）。
- **按轮次**模式：一轮只有一根柱，把该轮各步的标记**合并**到这一根上；一轮里有多个事件时显示 `✂×N`（不许把事件吞掉）。
- **✂ 自身也必须有提示**：鼠标移上去（或键盘聚焦）显示与该柱相同的那张提示卡，其中逐条列出事件：
  `✂ 压缩：压缩上下文（摘要替换 N 条消息）` / `✂ 剪枝：剪枝工具输出`。
  点 ✂ = 跳到那一次请求（与点柱子同效）。**没有说明的图标等于没做** —— 用户第一次看到时就是这么问的。
- 事件类型文案：`compaction` = **压缩**、`prune` = **剪枝**（与参考插件 i18n 的 `kind.compaction` / `kind.prune` 一致）。
- 左下「上下文事件」卡片列出每个事件：`#seq · ✂ 类型 · 说明 → 标在第 T 轮 · 第 S 步`，与柱子上的标记是同一条。

### R1.12.1 「上下文事件」卡：**会变的**与**不变的**必须分开呈现

- **会变的**（随你选的位置变化）做成**事件行**：每行给 `✂` 图标、事件名、它的说明、发生在第几轮第几步，
  以及状态徽章 **`已发生`（实心、左侧品牌色竖条）** / **`尚未发生`（虚线、降透明度）**。
  顶部一行汇总：`看的是 第 N 轮 · 第 M 步 这一刻 · 已发生 X · 还没发生 Y`。
- **不变的**（这一栏到底干什么用）收成**底部一行小字**，不占视觉重量。
- 用户 2026-10-01 的两条原话："内容是不变的，不拟真"＋"都堆在一起、都是这种浅灰色，不是很醒目"。
- 位置一变，`已发生/尚未发生` 的划分必须跟着变（同一会话早期那一步会看到"尚未发生"）。

### R1.13 右侧的轮/步选择器 + 对比基线（`docs/11` D30/D32）

- **两级选择器（我们的有意偏离，唯一一处不像上游）**：`轮` 下拉（T 项，每项 `第 t 轮（共 N 步）`）→ `步` 下拉（只列**当前离线那一轮**的步，`第 s 步（共 N 步） · HH:MM`；仅当轮为**末轮**时多一项 `当前（下一次请求）`）。
  **为什么偏**：`docs/05` §1.5 的量级约束 —— 单下拉要列**整段历史的每一步**，列表规模是 N；两级把它降到 **T + S**。实测（Chromium，1000 轮 × 4 步）：**单下拉 4000 项 = 75.0ms，两级 1000+4 项 = 9.2ms**（`measure-log` §30）。
- **对比基线（照上游 0.60.0 抄）**：`比前步` / `比前轮` 两个按钮，title 写清口径 ——「变动对比的基线：比前步＝与上一步对比；比前轮＝与上一轮最后一步对比（首轮无基线，全部计为变动）」。
  它决定分类行那两个 δ 标记（数量变动 / token 变动）**跟谁比**；首轮没有基线 ⟹ 全部计为变动。默认 **比前轮**。
- 与左侧趋势**必须始终一致**（交叉比对应当逐项相同；R1.11 的步级快捷片已作废）。

### R1.14 趋势图的 hover 提示（**自绘**，一律不用原生 `title`）

- 鼠标移上去、或键盘聚焦柱子时**立刻**出现 2 行提示；提示 `pointer-events: none`，不许挡住柱子。
- **第一行 = 位置**（两种粒度的文案不同，逐字照参考插件）：
  - 按步骤：`第 {t} 轮 · 第 {s} 步 (共 {n} 步)`
  - 按轮次：`第 {t} 轮 · 共 {n} 步`（该轮只有 1 步时写 `第 {t} 轮 · 共 1 步`）
- **第二行 = 数值**：`合计 ≈ {n}`；聚焦某类时 `{类别} ≈ {n}`；增量模式 `Δ {n}`（带正负号）。
- 该柱若挂有压缩/裁剪标记，**再加一行** `✂ {事件名}`。
- **必须渲染在横向滚动容器之外**：放在滚动内容里会撑大 `scrollWidth`，导致 hover 时滚动条开合、整张卡片跳动；
  提示用 `transform` 夹在可视区内（左右都不越界）。
- **触屏没有 hover**：点柱子选中后提示**常显**（换一根或滑走才消失）→ 手机上同样能看到"第几轮/第几步"。
- 原生的 `title` 一律不用（有延迟、手机上不出现）—— 照参考插件的做法。

### R1.15 柱体 = **按类别分色堆叠**（照参考插件 `dsh-context` 的 `lc-cat-seg`）

- 每根柱子不是"一根单色柱"，而是**按右侧分类树的那一套类别切段**：颜色 = 类别（与分类树同源同色），
  段高 = 该类这次在该柱里的量；只有非零的类别才产生段。
- 总计模式：段自下往上堆（顺序与分类树一致）。增量模式：见 R1.6（正差向上、负差向下，颜色仍是类别）。
- 聚焦某一类（R1.8）时**只保留那一类**的段（其余不画），于是"聚焦"这件事在图上变得可见。
- **反例（不许再出现）**：整根一个品牌色 + 负数涂红 —— 那既看不出上下文构成，也让"增量"失去意义
  （用户 2026-10-01 明确要求照参考插件的做法）。

## 2. 右侧：行模型与动作条

### R2.1 哪些行有动作（**由实测能力决定，不是设计偏好**）
| 系统提示词 | ❌ | ❌ | ❌ | 上游该行不传节点对象；且宿主保护 node 0 的 system（`assertSystemHeadRewrite`） |
| 工具定义（schema） | ❌ | ❌ | ❌ | 它们是请求头里的 schema 行，不是 surface 节点 |
| **用户消息** | ✅ | ✅ | ❌ | **本插件的关注重点**；实测可连续改任意次 |
| **注入内容** | ✅ | ✅ | ✅ | 这类每轮会被宿主重新注入 → 改一轮漂一轮，必须引导固定 |
| **助手消息** | ❌ **不给「编辑」** | ✅ | ❌ | **平台两条规则互斥，assistant 的 replace 不可能成功**（`docs/01` F7.2）。给了按钮必然点下去报错 |
| 工具结果 | ✅ | ✅ | ❌ | 只能改内容文本与错误标记（宿主只允许改 `content`） |

> 按钮的**可见性分两档**（常用 / 高级）见 **R2.5**：注入内容与技能注入属常用档（每轮被重新注入、会漂，必须始终可见），
> 工具结果的「编辑」属高级档（默认收起，但留标记说明在哪打开）。
>
**助手消息为什么没有「编辑」**：按钮位置改为显示一个说明徽章 `助手消息改不了`，title 写明
「助手消息在平台上无法改写（两条规则互斥）：改不了。要纠正它，就在开启子会话时写在首条任务里。」
（**不承诺**"遮蔽整段"：多节点区间替换平台可行，但**不在 v1 的 UI 范围内**，见 §8 与 `docs/01` V9）

> **这些改动怎么进"后期的上下文快照"**（用户 2026-10-01 问："还有哪些内容可以编辑，作为后期的上下文快照吗？"）
>
> - **改动只在「开启子会话」那一刻写进新会话**（保存只写插件本地，当前会话的模型看不到）——
>   开子会话时它们被逐字拼进新会话的第一句话（`docs/11` D15）。
> - **改写以「新口径」的形式进入新会话**：写进它第一句话的是**改后的正文**（逐字）；父会话日志与原文**不动**。
>   （平台能力上仍存在「追加替换事件遮蔽原文」这条路，但按硬约束，本插件界面**不提供**写进当前会话的入口。）
> - **固定块（不变量）整套已删除**（`docs/11` D14）：不再有「钉住 / 固定块 / 漂移检查」这一层。
> - **`批注` / `写一句更正` / `版本历史` / `从这一版恢复` / `去改现在这条` 全部删除**（`docs/11` D18/D19）：
>   行内动作**只有 `编辑`**（有本地改动时多一个 `丢弃这条改动`）。用户 2026-10-02：「上下文的编辑我们都沟通好了，**只有编辑就行了**」。
> - **系统提示词 / 工具定义改不了**（它们不在 surface 里，且宿主保护 system）→ 要改这两类属于**装配层**（人格 / 指令 / preset），本轮不做（`docs/00` §4.1、M7）。
> - **助手消息改不了**（平台两条规则互斥，`docs/01` F7.2）：界面**不给任何动作**（只给徽章说明原因）；
>   它会随对话历史进子会话，**"开新会话"并不能把它删掉** —— 要纠正它，就在开启子会话的首条任务里写清楚。

### R2.2 动作条（行内，常驻可见）
顺序固定：`#seq` → `编辑`（可编辑的行**只有这一个入口**）→（有本地改动时）`已改（本地）` + `丢弃这条改动` →（改不了的行）一句说明（`助手消息改不了` / `已被 #K 接替` / 被压缩埋掉）

- **常驻可见**，不许只靠 hover（手机没有 hover）。
- 当前可见动作都要有可理解的说明；**插件里不渲染任何"飘在按钮左上角"的 `?`** —— `保存` 的去向说明改挂在按钮自己的 `title` 上（用户 2026-10-06 红框截图：「当编辑内容时，保存的右上角、左上角还是有问号没去掉」；那个角标当初是给**批注**动作做说明的，批注已整批删除，剩下的只有悬停提示，却正好压在「高级：思考文本」那一行上）。取消按钮直接显示 `取消（Esc）`。
- ⚠️ **demo 例外，且不许照搬进插件**：demo 的「保存」与「确认」上仍留着左上角飘的 `?`，那是**讲解模式**的说明锚点（点一下弹说明 —— 原型自带的"可点击规格书"能力），且被 `demo/DESIGN-BRIEF.md` 列为交给外部设计师时**必须保留**的视觉语言。插件没有讲解模式，所以插件不实现它。
- 触控目标 ≥ 44×44（窄屏 640px 以下按上游 `redline.css` 的做法放大）。

### R2.3 不能编辑时必须给原因（不许按钮凭空消失）
**判定按"行身份"**（是不是当前可见节点、底层是什么事件类型），**不按分类名**——完整矩阵见 **R4.6**。

- **已被遮蔽的原始节点 / 旧替换体**：不显示「编辑」，显示徽章 `已被 #K 接替` + title：
  「这一条已被后来的改写遮蔽：平台不允许再拿它当改写目标（所以这里没有「编辑」）。原文与旧版本仍留在会话日志里，模型看到的只是最新的那条。」
- **当前可见的替换体**：**仍然显示「编辑」**（可以继续改，`docs/01` F7）——不要因为"改过一次"就把整条链锁死。
  「助手消息在平台上无法改写（两条规则互斥，`docs/01` F7.2），所以这里没有「编辑」。要纠正它，就在开启子会话时把要求写在首条任务里；它会被新会话继承。」
- 会话不在本进程：整列动作条禁用 + 顶部说明条（R4.4）。
- 轮次未闭合：写入类动作**不出现**（不是禁用后点了报错），并在顶部说明条写原因。
- 系统提示词 / 工具定义行：无动作条，且**不渲染空的动作区**（不留占位）。

### R2.5 「高级编辑」开关（常用 / 高级 两档）

> 用户 2026-10-01 提议：技能注入 / 助手消息 / 工具结果 一般用户用不到，做成"高级编辑"。

  注入内容 ✅、**技能注入 ✅** 会漂（同族）；用户消息 / 助手消息 / 工具结果都是日志里的历史，**改了就定了、不漂**。
  真正的依据是**"用户需要动手的概率"**：
  | 档 | 哪几类 | 为什么 |
  |---|---|---|
  | **常用（始终可见）** | 用户消息 · 注入内容 · **技能注入** | 都是「**我告诉模型什么**」；消息说错了必须改，后两类每轮被重新注入（会漂） |
  ⚠️ `钉住这一段`（固定块/不变量）**整套已删除**（`docs/11` D14）：两档里都**没有**这个按钮；
  技能注入的「编辑」按底层事件类型给；助手消息没有任何动作，见 R2.1 / R4.6。
- **不许凭空消失**（R2.3）：收起时该位置显示 `高级编辑` 小标记，title 写明「打开顶部高级编辑开关即可看到」。
- ⚠️ **这个标记是"信息"、不是"按钮"，所以不许给「?」光标**（用户 2026-10-06：「高级编辑处也有问号，鼠标移上去有问号，**但点不了**，在工具结果那里」）。
  `cursor: help` 画出来的是**问号箭头**，会被读成"这里能点/有说明"，而这个标记点不了 ⟹ 光标回到普通箭头，说明只靠 `title`。
  同一条规矩适用于**所有信息型标记**（`.redline-chip-soft` 的原因徽章 `助手消息改不了` / `已被 #K 接替`、编辑器里的 `.redline-dest` 去向标记、堆叠条的留白带）。
  机械门禁：`scripts/css-closure.mjs` **②‴**（我们客户端样式里 `cursor: help` 必须为 **0 处**，白名单当前为空；反向验证过）。
  ⚠️ **demo 不适用**：demo 的 `?` 是**可点**的讲解锚点，那里 `cursor: help` 是对的（见 R2.2 的同一处说明）。
- 开关**默认关**；它只影响按钮可见性，不改任何数据。

## 3. 行下内联编辑器

### R3.1 形态
**在那一行下面展开**，不弹窗（弹窗会盖住上下文，而用户要对照着上下文改）。同一时刻只有一个编辑器。

### R3.2 字段按内容类型决定（kind-aware）
编辑器字段由**底层事件类型**（宿主给的 `type`）与分类**共同**决定：

| 底层类型 | 编辑器字段 |
|---|---|
| `user/message`（含"注入内容""技能注入"里底层是 user 的） | **正文**（必填）+ 思考文本（可选，折叠在"高级"里） |
| `tool/result` | 结果文本 + `isError` 开关 |

> 早期那次尝试 的编辑器对五种类型显示**同一套字段**（连用户消息都给"思考文本"），实现时必须先按类型选字段。
> **用户消息 / 注入内容的主字段就叫「正文」**（不叫"可见文本"），并写明"模型看到的就是这一段"；
> **思考文本必须折叠在「高级」里**（`<details>`，默认收起）—— 用户 2026-10-01 实测问过"用户的消息不就一条吗？为什么是两条"。
> 界面上不解释"思考文本是什么"是错的——它是模型可见的 reasoning 块。

### R3.2.1 改第二次（当前 demo）
「编辑」只针对**当前可见的那一条**。所以：
- 改完一次之后，**同一条还在那里**（现在是替换体），可以**再改**；
- **被遮蔽的原始行**永远不能再直接当目标（平台会拒，别给按钮）。当前 demo 不提供 apply/回滚；可继续编辑的是本地保存的当前版本。

### R3.3 保存语义必须在编辑器里写明（当前 demo）

- 编辑器字段旁写明：`只写本地 · 开子会话时才带进去`。
- 点「保存」：**只写插件本地**；当前会话日志不变，当前会话的模型看不到这次改动。
- 行上只显示一个 `已改（本地）` 标记；再次点「编辑」预填最新版；同一行再次保存覆盖同一条本地改动。
- 点「丢弃这条改动」：清掉本地改动；如果编辑器正打开，编辑器收起，行恢复原文。
- 唯一写入点是「开启子会话」：确认框列出本地改动，确认后把改动逐字带入新会话第一句话。

**R3.3.1 当前 demo 的确认框**

- `保存` 不出确认框，因为它不写会话。
- 「开启子会话」才出确认框：列出从哪儿开始、会写进去的本地改动、首条任务、不会带上的内容与取消语义。
- 首条任务必须由人填写；插件不生成任何进入会话的文字。

**R3.3.2 输入去向**

编辑器的正文、思考文本、工具结果文本与错误标记都显示 `只写本地 · 开子会话时才带进去`；确认框的首条任务明确写着它会成为新会话第一句话。
这个标记也是**信息型**：虚线 + `title`，**不给「?」光标**（理由与门禁见 R2.5 那条）。

### R3.4 正文来源必须是全文（**硬性**）
- 预填的正文来自 `node.read`（宿主全文），**不得**把列表行上的 80 字预览塞进编辑器。
- 多段文本会被合并为一段，编辑器上方显示提示：`这条消息有多个文本段落；改写后会合并为一段。`
- 当前 demo 的长消息用于验证"列表预览 ≠ 编辑器全文"；保存只写本地，之后继续编辑仍预填最新版，开启子会话时才携带。

### R3.5 键盘与失败（当前 demo）

- `Esc` 关闭编辑器；`Cmd/Ctrl + Enter` 提交。
- 保存失败时保留输入，并在编辑器内显示原因。

### R3.6 取消语义（当前 demo）

- 点 `取消（Esc）` 关闭当前编辑器，不清掉已保存的本地草稿。
- 点 `丢弃这条改动` 会清掉该行本地改动，并收起该行编辑器。

## 4. 全局状态与回执

### R4.1 本地改动的可见状态（当前 demo）

- 当前 demo **没有**「还有 N 条未生效」吸顶条，也没有「全部应用」按钮。
- 有本地改动的行只显示一个 `已改（本地）` 标记；动作是 `编辑` 与 `丢弃这条改动`。
- 被遮蔽/被压缩/助手消息等不可编辑行只显示人话说明，不给其它动作。

### R4.2 写入与确认（当前 demo）

- `保存` 不写会话，也不出确认框。
- 「开启子会话」是唯一会写入新会话的入口；它的确认框逐条列出本次会带入的本地改动。
- 当前 demo 不提供 apply、批量应用、版本历史或回滚入口。

### R4.3 会话未结束 / 会话不在本进程

- 轮次未闭合：编辑器下方显示 `当前轮次还没结束 —— 改动只能在轮次边界提交。`。
- 会话不在本进程：编辑器显示 `这个会话不在本进程里，只能查看，不能编辑。`。
- 当前 demo 没有额外的「刷新」按钮；状态由顶部演示开关模拟。
- **插件侧同一道门有两层**（M3 已实现）：界面按 `turnState` **禁用 `保存` 并写明句子**（与 demo 的 `blocked = turnOpen || !live` 逐字一致）；主机侧**同样拒绝**（`redline/turn-open` / `redline/not-live`），
  界面只是体验、主机才是安全网 —— 因为保存虽然只写本地，但"为一次会话写入做准备"这件事不该发生在一个仍在动的 surface 上（`docs/01` F8）。
- 顶部「官方团队可用」开关关闭时，显示"本机未启用官方智能体团队"，团队相关对接点隐藏；当前 demo 本身不提供团队操作。

### R4.6 行身份 × 状态矩阵（**实现者不许自己猜**）

"行"的身份比"分类"更重要。判定**按身份 + 状态**，不按分类名：

| 行身份 | 有草稿 | 轮次未闭合 | 会话不在本进程 | 界面表现 |
|---|---|---|---|---|
| 原始节点 | ✅ / ❌ | **是** | 否 | 写入类动作**不出现**；顶部说明条解释原因（R4.4） |

## 5. 子会话面板（M5）

### R5.1 位置与内容（当前 demo）

子会话卡在右列上下文浏览器下面，当前只包含两块：

1. **开子会话**：一个常驻 `开启子会话` 按钮。保存的本地改动会在确认时逐字带入新会话首条任务。
2. **子会话索引**：只读显示 demo 中已经创建的子会话及其状态；不在卡片内重画子会话对话。

当前 demo 不提供固定块、冻结记录、派活、官方任务、压缩、打断、待处理结果或自动回流入口；这些属于后续插件阶段，不是当前 demo 契约。

### R5.1.1 当前 demo 的子会话状态

- 运行中的子会话显示只能看、不能改；空闲的子会话显示可以进入后继续编辑。
- 当前 demo 只展示状态说明，**不实现跳转**；插件阶段同样不给跳转按钮 —— **2026-10-06 实证理由**（`docs/01` **F55**）：第三方客户端插件**没有**"打开某个会话"的服务（官方子代理包对 `ctx.sessions` 只用 `list`/`retain`/`refreshProjections`，它把子会话**渲染**进来是它自己的 UI 行为），所以我们的索引只做两件事：**如实说清状态**（读 `turnState`）与**指名去哪儿打开**（父会话页头右侧的「N 个子智能体」目录）。

### R5.1.1 后续插件阶段：为什么**不**在左侧会话列表里嵌子会话（非当前 demo）

官方 UI 包 `dsh-client-ui-subagent`（已随运行时挂载）在自己的 README 里写着：
**"普通会话侧边栏会省略 subagent 对话，因此父会话页头目录是它们的导航入口。"**
它的做法：父会话页头的标题当**谱系面包屑**，操作区放**后代数量触发器**（悬停 150ms 打开目录树、按需加载任意深度），
点一个后代就以确切地址打开它的对话（空间允许时优先在**右侧 Sidebar** 独立分栏），
行上显示 mode / 活动状态 / title / token / 活跃轮次耗时；**可续接**子会话在那里还有普通输入区和独立 **Stop**。

**所以我们的设计是**：
- **不重画会话树、不在左侧列表嵌套子会话、不在面板里复制一个对话视图**；
- 我们的「子会话」面板 = **父会话视角的索引 + 动作 + 跳转**（索引看"有什么待处理"，跳转看全文）；
- 好处：① 不和官方 UI 打架；② 用户用的是官方那个功能完整的视图；③ 我们不必维护会话树的一致性。

### R5.1.3 后续插件阶段：子会话的上下文编辑（非当前 demo）

> 用户 2026-10-01 问：主会话负责收集汇总、子会话干重活（一个子会话可能跑上千轮），
> 这种情况创建子会话之后，"子会话可以对上下文进行编辑吗"？——他说在官方智能体团队模式下
> **看不到子会话的上下文**，所以怀疑改不了。

- **能编辑，关键动作是「打开它」**：子会话是**真会话**（独立 `sessionId`、独立日志、持久化，`docs/01` §F13）。
  我们的面板挂在**会话视图**上，永远显示"**当前标签页选中的那个会话**" ⟹
  用官方谱系目录（父会话页头）或右侧 Sidebar 打开子会话后，面板就切到**它的**上下文，
  编辑能力与父会话**完全一样**（只有 `编辑`）。**不需要两套界面。**
- **为什么"在父会话里看不到、也改不了它"是正常的**：`apply` / `annotate` 要求目标是**该会话自己的 live Agent**
  （`docs/01` §"会话不 live 时对接点全不可用"）；官方 Agent Teams 面板只提供**成员导航 + 只读任务板**（`docs/01` F30），
  它本来就不承担"编辑另一个会话的上下文"。所以我们不做"跨会话就地改"，只做**跳过去、在它自己的视图里改**。
- **两条前提**（都必须在界面上如实说出来，不许等用户点了才发现）：
  | 前提 | 拿不到时 | 界面怎么说 |
  |---|---|---|
  | **轮次闭合** | 子会话正在跑（几乎总在跑）→ 写入类动作**不出现** | `运行中：打开它 = 面板切到它的上下文；轮次闭合前只能看，不能改（要改就先等它空闲或打断）` |
  | **在本进程** | `ctx.agents.get(sessionId)` 拿不到 → 只能只读 | `这个子会话当前不在进程里，只能查看。`（口径同 R4.4） |
- **给这种用法的建议流程**：要改子会话 → **趁它空闲**（或先 `打断`）→ 打开它 → 改 → 让它继续。
  "跑上千轮的长子会话"本身没有错，但**改它的窗口只在轮次之间**。

### R6.4 移动端适配（**设计进去，不是断点堆出来**）

参照参考插件：主布局**没有一处 `@media`**，靠的是流式与容器查询。

- **V9 流式列**：两列用 `flex: 1 1 min(420px, 100%)` + `flex-wrap: wrap` → 窄屏自动单列，宽屏自然两列。
- **V10 卡片内自适应用容器查询**：卡片 `container-type: inline-size`，内部用 `@container (max-width: …)` 改排布。
- **V11 真触屏才放大**：`@media (pointer: coarse)` 下把可点区域提到 **≥44px** —— 用 pointer 判断，**不要**用窗口宽度（桌面窄窗口不是触屏）。
  ⚠️ 2026-10-02 补齐两类**曾经漏掉**的小目标（用户报「17 点了没有反应」时一并发现）：
  · **讲解模式序号**（`.exnum`，实测 16×15px）与 **✂ 事件标记**（`.mark`，24×16px）—— 它们都是**真实节点**，
    粗指针下必须用透明 `::after` 撑出 ≥44×44 命中区（`demo.css` coarse 分支；实测序号命中区 **48×44**）；
  · 序号贴宿主左上角、**上方撑不开**（会被上一行元素挡住）⇒ 命中区**向下多留**。
- **V12 横向滚动条**：统一 `overscroll-behavior-x: contain` + `-webkit-overflow-scrolling: touch` + `touch-action: pan-x`，
  并由 JS 兜 WebKit 的横向 wheel（见 R1.9）——**滑到头不许把整页带走**。
- **V13 安全区**：底栏/抽屉/弹窗用 `env(safe-area-inset-bottom)`，顶栏用 `safe-area-inset-top`（iPhone 手势条与刘海）。
- **V14 页面不横向滚**：`body { overflow-x: hidden }`；横向滚动只发生在卡片内部的滚动条里。
- **V15 iOS 字号不放大**：`-webkit-text-size-adjust: 100%`。
- **V16 长文本不撑破**：错误码、正文、理由等一律 `overflow-wrap: anywhere`。

> 原始测量数据、截图与两个由实测抓出的问题：[`demo/screenshots/measure-log.md`](../demo/screenshots/measure-log.md)。
>
> **讲解模式的硬规矩（2026-10-01 由用户的实测反馈定下）**：讲解模式**只许加编号，不许改变被测元素自己的样子**。
> 1. 高亮**只能画在伪元素（`::after`）上**，不得给元素自身设 `outline`/`background`/`border` ——
>    否则 `body.explain [data-explain]` 的特异性（0,2,1）会盖掉元素自己的状态样式。
>    实测事故：开着讲解模式时趋势柱体的 hover 与「选中」整片失效，所有柱子长得一模一样（用户因此以为柱体没有 hover/选中反馈）。
> 2. 高亮**跟着编号走**：只有真正挂了编号的元素才被标亮（否则趋势图里几十根柱子会各自带一个虚线框，图表就不像原样了）。
> 3. **同类重复元素只标一个编号**：趋势柱体只标**当前选中的那根**、轮次刻度只标第一格，其余行为相同、不重复标。
> 4. **编号连续、且顺序由"元素类别"决定**（＝按讲解词典的先后排，再依次编 1..N），
>    **不按出现顺序现数**：按出现顺序数的话，切换按轮次/按步骤时前面的元素个数会变
>    （步骤模式多一个 ✂ 标记、轮次模式没有刻度格的 `data-explain`），实测"点轮次时第 1 步是 18、点按步骤时变成 20"。
>    也不直接用词典序号当编号 —— 那会留下空号（实测缺 9/13/16/17/22/23/25，用户问"这些在哪里"）。
>    两者兼顾后：**编号 1..N 连续**，且切换粒度时柱子的编号不变。
> 5. 讲解模式**不占用**元素的点按：序号是独立节点，只吃掉自己那次点击（见 `docs/10` M05-22）。
> 6. 编号节点必须挂在**能装子节点**的元素上：`select` / `input` / `textarea` / `img` 装不下 `<span>`，
>    塞进去会被浏览器直接丢掉 → 那类元素要**外面包一层**（本插件里是 `.pickwrap`）再把 `data-explain` 挂到包层。
>    实测事故：步骤下拉的编号 11 一直"看不见"（用户问"11 编号在哪里？"）。
> 自动化护栏：`demo/check-static.mjs` 的第 4/5/7/8 条契约 + `demo/check-runtime.mjs` 的讲解模式/主题用例组。
>
> **自检工具的位置**：「自测面板」（自报元素尺寸、横向溢出、趋势柱数与刻度）是**验证工具**，不是给用户的功能，
