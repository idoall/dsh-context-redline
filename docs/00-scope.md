# 00 · 范围（Scope）

> 本文件回答三个问题：**要做什么**、**不做什么**、**做到什么程度算完成**。
> 评审请重点看 §2 的"非目标"与 §3 的"成功标准是否可验收"。

## 1. 一句话

> **当前 demo 边界**：当前可交互原型只验证「看上下文 → 编辑 → 保存到本地 → 开启子会话时携带本地改动」；
> 压缩、派活、官方团队、漂移检查、固定块等属于后续插件阶段，不是当前 demo 已有功能。

把 DSH 的「上下文浏览器」（只读，见 `docs/` 里的图 1 描述与上游 `dsh-context`）升级为**人来批改上下文的工作台**，并把
**编辑 → 开子会话 → 压缩 → 主会话指挥子会话** 串成一条可点的主线，
用「保存本地改动 + 开子会话时逐字携带」承接已改过的历史；固定块/漂移治理/压缩属于后续插件阶段。

### 2.2 非目标（明确划掉，避免范围膨胀）

| # | 不做 | 为什么 |
|---|---|---|
| N1 | **不做"删除历史"** | DSH 的会话日志是 append-only；能做的只有**遮蔽**（模型看不到、日志仍在）与 **compaction**（体积变小但不可逆）。UI 上禁止出现"删除"字样 |
| N3 | 不改写**历史请求**的构成 | 写入只作用于**当前及未来** surface；过去某一轮的构成是既成事实，只读展示 |

| N7 | 不跟随上游未发布更新 | 基线固定在 tag `v0.59.2`，按需 cherry-pick |
| N8 | 不动 DSH 安装目录与 `$DSH_HOME` 下的配置/脚本 | 用户硬约束（见 `AGENTS.md` §1） |

## 3. 成功标准（每条都可验收）

> 每条都写成"能在界面上指出来 / 能在测试里断言"的形式。

**S1 轮次 → 构成（G2）**
左侧趋势图点某一轮/某一步，或用右侧浏览器标题里的两个选择器（先选轮、再选该轮步骤；末轮步骤多一项 `当前（下一次请求）`）→ 右侧浏览器切到该轮末步/该步，分类行显示条数 / token / 占比与非零 δ。
*验收*：与同一轮在下拉选择器里选中末步的结果**逐项一致**（人工门禁，两个入口交叉比对）。

> **S1.1 计数契约（否则"一致"可能只是"错得一样"）**
> - **注入内容 N** = 该步 surface 中、**按节点计**数（不是按文本块计）满足"注入类"判定的节点个数；
>   "注入类"的口径 = 宿主 fold 给出的分类（`source.kind` 非空且 ≠ `user`，或带 `source.form`）。
> - **用户消息 N** = 同类口径下 `cat === 'user'`（真·用户消息，不含注入）。
> - **token** 用宿主投影里该节点的 `tokens`；**缺失时显示 `—`**，不得用 0 冒充。
> - **占比分母** = 该步 surface 的合计 token（与上游既有的分类行口径一致）。
> - 测试样本必须包含：多文本块消息、token 缺失项、已被遮蔽的节点（它们**不计入**当前步）。
> - **同一条替换体只能计一次**：它同时挂在"已应用清单"与"追加节点清单"上是**同一件事的两个索引**，
>   重复计入会让它**渲染两遍、token 也算两遍**（2026-10-02 用户实测：注入内容里 `#1600` 出现两次、条数 5 变 7）。

**S2 用户消息可编辑（G1 + G3）**
在右侧浏览器展开「用户消息 / 注入内容 / 技能注入 / 工具结果」中的可编辑行 → 行上有 `#seq` 与「编辑」→ 行下展开编辑器 → 点「保存」只写本地，行上显示 `已改（本地）`；再次编辑预填最新版；点「开启子会话」确认后才把改动逐字带进新会话首条任务。
*验收*：保存不写当前会话日志；再次编辑能继续修改；丢弃本地改动会收起编辑器并恢复原文；开启子会话确认框逐条列出并带入改动。

**S3 全文不丢字（G3）**
编辑一条**长消息**（> 200 字、含多段换行）→ 编辑器里看到完整正文；不改内容直接保存 → 显示本地无实质改动；改一个字保存 → 本地草稿保存完整正文（当前会话不变），可继续编辑；点「开启子会话」确认后才逐字带入新会话第一句话。
*验收*：路由级测试断言"编辑器预填文本 == 事件里的完整正文"，且**不等于** 80 字预览。这条直接封死早期那次尝试 的致命缺陷（`docs/01` F35）。

> **S3.1 已知语义（必须写进界面）**：改写把消息的多个文本块**合并为一段**；`reasoning` 单独保留。界面上要提前说明，不让用户事后发现。

> **S3.2 哪些行真的可改（实测决定，见 `docs/01` F7.2）**
> - **用户消息 / 注入内容 / 技能注入 / 工具结果**：可改写（工具结果只能改内容文本）。
> - **助手消息：不可改写**（平台两条规则互斥）⟹ 界面上**不给任何动作**，只给徽章 `助手消息改不了` 说明原因（开新会话并不能删掉那条助手消息）。
> - **系统提示词**：不可改。
> *验收*：每一种行类型的按钮集合都有单测锁定；点下去不可能出现"平台报错"。

**S4 固定块与漂移（G4）—— ⛔ 已作废**

固定块、钉住、漂移检查和重注入不属于当前 demo，也不属于本轮 UI 契约；本编号只保留用于历史追溯。当前语义是：保存只写本地，开启子会话时把本地改动逐字带入新会话第一句话。

*S5.1 改动随开子会话写进去（⚠️ 用户 2026-10-02 立的**硬约束**）*：**所有保存都是临时保存**（只写插件本地，当前会话的模型看不到）；
点「开启子会话」时，把当前所有本地改写**逐字拼进那个新会话的第一句话** —— 这就是「只有开启子会话时才写进去」。
确认框里列清「会写进去 N 条改写」；**没有本地改动也允许开**（那就是原样继承）。
*验收*：① 单测断言保存**不写会话日志**；② 断言开子会话时本地改动逐字出现在新会话的第一句话里。

*S5.2 冻结记录 —— **已删除**（`docs/11` D10）*：不再有"冻结记录"这一层（切点 / 条目数 / 备注 / 版本 / 逐字正文全部随之删除）。
理由：平台 fork 的种子**恒为**"当前最后一个 `turn/end` 及其之前"，调用方**没有任何参数**能指定更早的切点（`docs/01` F38）⟹ 记录**从未真正决定起点**。
**仍然必要的一条**：开子会话时把**当前本地改动**逐字写进新会话第一句话（S5.1；固定块/不变量已随界面减法删除，见 `docs/11` D14）。
*验收*：单测断言"开子会话"不写父会话日志；确认框里**不出现**"记录 / 切点 / 起点可选"这类说法。

*S5.3 「允许创建」确认框（demo 当前口径）：点「开启子会话」后，在面板内弹出确认框，逐项列出：
① **从哪儿开始**：本会话「最后聊完的那一轮」为止——平台自己算的，改不了；
② **会写进去的改动**：本地保存的改写逐条列出，并说明会逐字带进新会话首条任务前；
③ **首条任务**：人写、必填；④ **不会带上**：父会话后续新轮次与工具授权；⑤ **取消**：什么都不发生。
保存本地草稿**不会阻止**开启子会话；确认时直接把当前本地改动逐字带入新会话第一句话。
*验收*：取消不建会话；确认后新会话存在且首条任务包含人写任务和本地改动。

*S5.4 压缩：**当前 demo 未提供压缩操作入口**。压缩的真实平台能力与 M4.5/M5 测试计划分开验证，不在本 demo 交互契约内。

*S5.5 派活/官方团队：**当前 demo 未提供派活、团队任务、打断或自动回流入口**；这些不是当前 demo 的可验收功能。

*S5.6 授权：当前 demo 只对「开启子会话」显示自己的确认框；其它平台写入能力不在 demo 里。

**S6 并存（G7）**
装上本插件后，`dsh-context@0.64.0` 的面板照常工作；控制台无 `already registered` / `loaded without registering` 报错。
*验收（必须可复现，不是"我没看见错"）*：同一 profile 同时启用两个插件 → **依次**打开两个面板，并各触发一次只读路由（`detail`）→ 保存 **`dsh web` 启动日志** 与 **浏览器 console 全量片段**，断言其中不含指定错误字符串。

**S7 工程质量**
`tsc --noEmit` exit 0；`vitest run --project edit --project channel` 全绿；每条护栏测试**反向验证会真红**（改坏实现 → 看它红 → 改回），并把这一步写进提交说明。
*验收*：命令输出原文 + 反向验证记录（`docs/05` §6 的四个具体例子）。

**S8 回滚：**⛔ **当前 demo 不提供版本历史 / 回滚 / 恢复入口**（`docs/11` D19）。平台能力背景若需复核，放在平台事实和专门测试计划中，不作为当前界面契约。

**S9 主会话不膨胀（G10，可观测；后续插件阶段，不是当前 demo 功能）**
一次派活周期内：主会话**不调用开发执行类工具**（bash/edit/write 等）；其事件数增量只来自**人的决策**与 `child.prompt`。
*验收*：真机记录派活前后的**父会话事件数**与**字节增量**，并逐条说明每一条增量是什么。
**取舍**：若 token 口径不可靠就**只用事件数/字节**，并**删掉"控制规模"这类口号**——不许留无法判定的自我表扬。

**S10 能力开关对成功标准的影响（M4.5/未来插件阶段；不是当前 demo 功能）**
M4.5（`docs/04`）会把平台能力验成一组**布尔开关**（`sessionQuery` / `agents` / `fork` / `compaction` / `rollbackHistory`）。
开关为 false 时，**本节的 S 条按下面这一档解释**，并且界面上**不允许出现"开关为 false 但按钮还在"**：

| 开关 | 若为 false | 受影响的 S 条（届时按此改写并留 diff） |
|---|---|---|
| `compaction` | 没有压缩后端 → 只做体检与记录 | S5.4 改为"引导你在子会话执行 `/compact`"；`docs/03` R5.3 **不显示执行按钮** |

## 4. 与图 2 那套"上下文装配"的边界

图 2（微信群截图）那份能力清单里，**同一份能力其实混了三件事**。我们把它们分开，只做前两件：

| 图 2 的条目 | 属于什么 | 我们怎么处置 |
|---|---|---|
| ① 拍快照 | **会话快照** | ⚠️ **已删除**（`docs/11` D10）：平台种子恒为"最后聊完的那一轮"，快照决定不了起点；该需求由「开启子会话」承接 |
| ③ 整体注入一个新会话 | **会话生命周期** | ✅ 做（G5，M5）——用平台原生 fork，而不是自己拼一个会话 |
| ⑤ 给一个正在用的会话注入新能力描述 | **宿主能力**（`ctx.systemPrompt.section` / `agent.inject`） | ⏸ 标为 M7+：这属于"改宿主注入源"，与 N6 的"不产生 AI 内容"要一起想清楚谁写这段文字 |
| ② 复制 → 改块/加块/改人格/追加内容 → 编译 → 标成模板 → 组装（extends）→ 解析 | **另一个产品面**：提示词/人格/块的**模板与装配** | ❌ 本轮不做（N5）。它需要的是"块库 + 继承 + 编译"，与本插件的"改会话里已有的那一条"是不同的数据模型 |
| ⑥ 四个入口都能用（工具 / 命令 / RPC / 内部服务） | **接入方式** | ◐ 做三个（RPC / 主机斜杠命令 / 内部服务），工具入口见 N6 与 `docs/08` |

### 4.1 关于 ② 的**明确决策框**（已拍板，不是"以后再说"）

| 项 | 内容 |
|---|---|
| **本轮是否交付** | ❌ **不交付** —— ✅ **已拍板**（2026-09-30 用户裁定 `docs/08` Q2 = 推荐 A） |
| **前提产物（M7a 的入口条件）** | ① **块模型**：块的身份/版本/继承语义；② **模板与 extends 语义**：谁继承谁、冲突怎么裁；③ **编译与解析契约**：从块到"一条可注入的消息"的确定性变换；④ **装配结果预览**：装配出来的东西长什么样、会丢弃什么 |
| **落地边界（硬性）** | 装配结果**只能**经本插件的 `apply`（遮蔽）或 `inject`（追加）落地——**不许**绕过写入器直接 append，否则"我改的这条到底进没进模型"就再也说不清了 |
| **退出条件（已完成）** | ✅ `docs/08` Q2 已由用户在 M0 内拍板（本轮不做、M7a 前置改为"先盘官方那套缺什么"），结果**已回写**本节与 `docs/04` 的 M7+ 表；M1 的开工前提（Q1/Q2/Q11）**全部满足** |
| **为什么不做** | 见上方正文（数据模型不同）；更硬的理由是**官方已有一整套**（preset / persona / instructions / 补丁方言），我们再做就是第二套真相（`docs/08` Q2 理由 1–3） |

## 5. 谁用、什么时候用（用户故事）

| # | 场景 | 期望 |
|---|---|---|
| U2 | 我上一轮的话说得不清楚，导致后面全歪了 | 左侧点那一轮 → 右侧展开「用户消息」→ 改那条 → 开启子会话 |

## 6. 术语（评审时统一口径）

| 词 | 含义 |
|---|---|
| **surface** | 模型当前能看到的内容集合（宿主权威）；日志里的原文可能**不在** surface 上 |
| **遮蔽（redact / shadow）** | 追加一条 `surfaceOp:{op:'replace'}` 事件，把原文从 surface 上拿掉；**原文仍在日志里** |
| **本地改动** | 我们自己的本地数据（不写会话）；点「开启子会话」时才逐字写进新会话的第一句话。两类：**改写**（可编辑的行）与**比更正**（只给改不了的行：助手消息 / 被压缩埋掉） |
| **轮次 / 步骤（turn / step）** | 宿主概念：一轮里若干步，每步一次模型请求 |
| **快照（freeze）· 已删除** | `docs/11` D10 把"冻结记录"整套删掉了：它记的切点决定不了起点（平台恒取最后聊完的那一轮，`docs/01` F38），所以只留「开启子会话」一个入口 |
| **子会话（child session）** | 用父会话**已完成轮次**做种子新开的会话；父会话其后新轮次**不会**进去。它是**真会话**（有自己的 id 与日志），但**不出现在左侧会话列表里**——导航入口是父会话页头的血缘目录（官方行为，`docs/01` F13.1） |
| **可续接子会话** | 长期存活、可反复收后续消息、可单独 Stop 的子会话（`startContinuable`）；**收工时由平台往父会话追加结算通知** → 主会话据此继续。**v1 默认用它**（`docs/06` §3.1） |
| **一次性子会话** | 只跑一次、以单个结果结算（`start`）；结果只回到调用方，**父会话不会被自动唤醒**（"模型自己用工具发起"那条路径除外） |
