# 00 · 范围（Scope）

> 本文件回答三个问题：**要做什么**、**不做什么**、**做到什么程度算完成**。
> 评审请重点看 §2 的"非目标"与 §3 的"成功标准是否可验收"。

## 1. 一句话

把 DSH 的「上下文浏览器」（只读，见 `docs/` 里的图 1 描述与上游 `dsh-context`）升级为**人来批改上下文的工作台**，并把
**编辑 → 快照 → 子会话 → 压缩 → 主会话指挥子会话** 串成一条可点的主线，
用「快照切断过去 + 逐字固定块守住未来」同时压制**上下文膨胀**与 **AI 漂移**。

## 2. 目标 / 非目标

### 2.1 目标（本轮之后的 M1–M6 要实现）

| # | 目标 | 归属阶段 |
|---|---|---|
| G1 | 右侧「上下文浏览器」的每一行可**编辑 / 批注 / 钉住这一段**（＝存为固定块，命名按 D7）；**用户消息**是重点（助手消息只可批注，见 `docs/01` F7.2） | M2 + M3 |
| G2 | 左侧选中某一**轮**可驱动右侧显示该轮构成；左侧每轮直接显示**用户消息 / 注入内容**的条数 | M4 |
| G3 | 编辑走**两步**：先存本地草稿（不进会话），再在轮次边界「应用到会话」（遮蔽原文） | M2 + M3 |
| G4 | 注入类内容可**逐字**固定为不变量，跨会话（含子会话）生效，并能**检出漂移**、**显式重注入** | M2 |
| G5 | 改完可**冻结快照**，用平台原生 fork 开**子会话**（带"允许创建"确认框），在子会话里**压缩**（压缩前如实列出将被替代的范围），主会话**逐批派活** | M5 |
| **G9** | **可回滚**：任一次 `apply` 都留下"历史版本"，人可选择一个版本**生成新的替换把内容恢复回去**（平台已实测可行：目标 = 当前可见的替换体；见 `docs/01` F7/F7.1）。这是图 2 ④「改前自动归档、能回滚」的兑现方式 | M2 + M3 |
| **G10** | **"主会话不随开发膨胀"必须是可观测的**：一次派活周期内，主会话**不调用开发执行类工具**；其事件数 / 字节增量只来自人的决策与派活，并在界面上显示这次派活的父会话增量 | M5 |
| G6 | 每个会**写会话 / 建会话 / 不可逆**的动作，事前列清单、单独授权 | M5 |
| G7 | 与已安装的 `dsh-context@0.60.0` **并存**，互不顶掉（我们的源码复制基线是 git tag `v0.59.2`，与"已装哪个版本"是两件事） | M1 |
| G8 | 有一份可评审、可执行、带验收人的路线图与测试计划 | M0（本文件集） |
| **G11** | **需求可追溯**：用户原话与图 2/3/4 的每一项能力，都能查到"做 / 不做 / 降级"及理由 | M0（`docs/09`） |

### 2.2 非目标（明确划掉，避免范围膨胀）

| # | 不做 | 为什么 |
|---|---|---|
| N1 | **不做"删除历史"** | DSH 的会话日志是 append-only；能做的只有**遮蔽**（模型看不到、日志仍在）与 **compaction**（体积变小但不可逆）。UI 上禁止出现"删除"字样 |
| N2 | 不自动开子会话 / 不自动重注入 / 不自动提交草稿 | 会在用户没看着的时候改会话或建会话 |
| N3 | 不改写**历史请求**的构成 | 写入只作用于**当前及未来** surface；过去某一轮的构成是既成事实，只读展示 |
| N4 | 不产生任何 **AI 生成内容** | 本项目存在理由：进入会话的每个字都必须来自人类输入（正文、标签、理由、子会话首条任务） |
| N5 | **不做图 2 的"上下文装配"整套** | 改块/加块/改人格/追加内容 → 编译 → 标成模板 → 组装（extends）→ 解析、整体注入一个新会话、一致性检查与合并——那是**另一个产品面**（见 §4），列为 M7+ |
| N6 | v1 不注册 model-facing tool | 见 N4：工具入口意味着模型可驱动"改上下文/建会话"。原生 `subagent*` 工具已经覆盖"主会话指挥子会话"，我们不必再开一个模型入口（`docs/08` Q3 = 🔧 **默认已定：v1 不做**） |
| N7 | 不跟随上游未发布更新 | 基线固定在 tag `v0.59.2`，按需 cherry-pick |
| N8 | 不动 DSH 安装目录与 `$DSH_HOME` 下的配置/脚本 | 用户硬约束（见 `AGENTS.md` §1） |

| 图 2/4 的项 | 我们的处置 | 降级到什么程度 | 替代路径 | 裁定（✅ 已拍板） |
|---|---|---|---|---|
| ⑥ 四个入口里的**「工具」入口**（模型可调用本插件） | ❌ v1 不做 | 只做 **RPC / 命令 / 内部服务** 三个入口 | 原生 `subagent*` 工具已覆盖"主会话指挥子会话"；本插件补的是**人的**批改台 | ✅ **已拍板**（`docs/08` Q3）：接受三入口；只读工具留到 M7，v1 不做 |
| ② **上下文装配**（复制→改块/加块/改人格→编译→模板→组装 extends→解析） | ❌ 本轮不做（M7a） | 只留**接口面**：装配结果只能经我们的 `apply` / `inject` 落地 | 见 §4 与 `docs/08` Q2 | ✅ **已拍板**（`docs/08` Q2）：本轮不做；M7a 单独立项，前置＝**先盘官方那套缺什么** |
| ⑤ 给正在运行的会话**注入新能力描述** | ⏸ M7b | v1 不做（与"不产生 AI 内容"的边界要一起定） | 固定块的漂移检查 + 显式重注入已能覆盖大部分场景 | ✅ **已拍板**（`docs/08` Q5，默认值）：v1 不做，M7b 再议 |

其余各项**全部做**（①拍快照 → G5；③整体注入一个新会话 → G5 的 fork；④一致性检查与合并 → `apply` 的草稿确认流程 + 日志留痕 + **新增的回滚 G9**；图 3 的"主会话不膨胀" → **G10 变成可观测目标**；图 4 的"允许创建"确认框 → G5 的 UI 条件）。

**Q1 包名 = `dsh-context-redline`** · **Q6 子会话 = 可续接（`startContinuable`）** · **Q11 = A 完整回滚** · **Q12 = A′（快照化子会话 + 对接官方 Agent Teams）**。

## 3. 成功标准（每条都可验收）

> 每条都写成"能在界面上指出来 / 能在测试里断言"的形式。

**S1 轮次 → 构成（G2）**
左侧趋势图轮次条点某一轮，或点「第 N 轮 · 第 M 步」卡片 → 右侧浏览器切到**该轮末步**，标题写明"第 T 轮（共 N 步，显示末步）"，分类行显示条数 / token / 占比。
*验收*：与同一轮在下拉选择器里选中末步的结果**逐项一致**（人工门禁，两个入口交叉比对）。

> **S1.1 计数契约（否则"一致"可能只是"错得一样"）**
> - **注入内容 N** = 该步 surface 中、**按节点计**数（不是按文本块计）满足"注入类"判定的节点个数；
>   "注入类"的口径 = 宿主 fold 给出的分类（`source.kind` 非空且 ≠ `user`，或带 `source.form`）。
> - **用户消息 N** = 同类口径下 `cat === 'user'`（真·用户消息，不含注入）。
> - **token** 用宿主投影里该节点的 `tokens`；**缺失时显示 `—`**，不得用 0 冒充。
> - **占比分母** = 该步 surface 的合计 token（与上游既有的分类行口径一致）。
> - 测试样本必须包含：多文本块消息、token 缺失项、已被遮蔽的节点（它们**不计入**当前步）。

**S2 用户消息可编辑（G1 + G3）**
在「用户消息」分类里展开任意一条**未被遮蔽**的消息 → 行上有 `#seq` 与「编辑」→ 点击后**在该行下面**内联展开编辑器 → 保存草稿后行上出现「未生效」与「应用到会话」→ 提交后行上显示「原 #N → 新 #M」。
*验收*：单元/路由级测试断言追加了 `surfaceOp:{op:'replace'}` 事件且原文被遮蔽；人工门禁确认内联、无弹窗、浅深主题都正常。

**S3 全文不丢字（G3）**
编辑一条**长消息**（> 200 字、含多段换行）→ 编辑器里看到的是**完整正文**；不改内容直接提交 → 宿主以"没有实质改动"拒绝；只改一个字提交 → 落进会话的正文与编辑器里**逐字一致**（除多段合并为一段这一条已知语义，见 S3.1）。
*验收*：路由级测试断言"编辑器预填文本 == 事件里的完整正文"，且**不等于** 80 字预览。这条直接封死早期那次尝试 的致命缺陷（`docs/01` F35）。

> **S3.1 已知语义（必须写进界面）**：改写把消息的多个文本块**合并为一段**；`reasoning` 单独保留。界面上要提前说明，不让用户事后发现。

> **S3.2 哪些行真的可改（实测决定，见 `docs/01` F7.2）**
> - **用户消息 / 注入内容 / 技能注入 / 工具结果**：可改写（工具结果只能改内容文本）。
> - **助手消息：不可改写**（平台两条规则互斥）。界面上**不给「编辑」按钮**，只给**批注**，并说明原因与替代路径（批注 / 快照+子会话；**多节点区间替换平台可行但 v1 不给 UI 入口**）。
> - **系统提示词**：不可改。
> *验收*：每一种行类型的按钮集合都有单测锁定；点下去不可能出现"平台报错"。

**S4 固定块与漂移（G4）**
把一条注入类内容**钉住这一段**（逐字）→ 换一个会话（或开子会话）仍能看到它 → 宿主要下一轮重新注入原文时，界面报告"漂移"→ 人点重注入才追加。
*验收*：测试断言 workspace 作用域跨 sessionId 可见、逐字判定（改一个字即算漂移）、退休后历史仍在。

**S5 快照 → 子会话 → 压缩 → 派活（G5）**
完整链路：**草稿清零（门槛）→ 冻结快照 → 「允许创建」确认框 → 开子会话 → 压缩前如实报告 → 压缩 → 派活 → 打断**。

*S5.1 草稿门槛（防"以为草稿进了子会话"）*：存在未提交草稿时，**「冻结快照」与「开子会话」按钮禁用**（或进入草稿清单），文案写明
`草稿不在 fork 种子里 —— 它只存在插件本地，不进会话日志`，并**逐条**给出处置（应用 / 放弃 / 返回）。
只有草稿数 = 0 才允许继续确认创建。
*验收*：人工门禁覆盖"有草稿 → 被阻止 → 清空/应用后放行"两条路径。

*S5.2 冻结记录*：`cutSeq`（最后一个 `turn/end`）· 条目数 · **人写备注** · 时间 · 在效固定块版本。**只写我们自己的库，不写会话**。
**字段口径（N4）**：这个字段**不叫「摘要」**，插件**不生成任何摘要文字**——它只存**人写的备注**（可选，空着也行）；若将来要存 `digest`，那是**内容哈希/计数**，不是自然语言。
*验收*：单测断言冻结前后**会话事件数不变**。

*S5.3 「允许创建」确认框（图 4 的真实体验，必须是可观察的 UI 条件）*：点「开子会话」后，**在面板内**弹出确认框，框内逐项列出：
① 种子范围（`cutSeq`，即"父会话已完成轮次"到哪一条为止）；② 首条任务（**人写**，必填）；③ 继承范围（继承对话历史；**不继承**工具授权与父会话权限）；④ 副作用（新建会话、种子**一次性**、之后父会话新轮次不会进去）。
**取消 = 不建任何会话**；只有确认后才调用 fork。
*验收*：人工门禁两条证据——"取消后 `child.list` 无新会话"与"确认后新会话存在且能看到父会话已完成轮次"。

*S5.4 压缩前"必须丢的如实报"（图 2 ③ 的同一条要求）*：确认框里列 `childId` · 将被**平台的压缩摘要**替代的区间与条目数 · **不可逆**提示（这段摘要由**平台**生成，不是我们写的）；
成功后显示**实际的** `compaction` 范围与结果（条目数/token）；失败显示**失败码 + 失败尝试是否留痕**。
*验收*：人工门禁看到"执行前清单"与"执行后实际范围"两屏；失败码覆盖 `busy`（等它空闲）与至少一个非 busy 码。

*S5.5 派活的端到端 DoD（图 3 的协作有效性）*：人在面板发一条**人写的开发任务** → 子会话状态由 idle 变 running 并**留下可核对的任务执行事件** → 主会话显示该状态 → 可**打断**并看到打断后的状态 → **子会话收工时，父会话日志出现 `subagent-settled` 结算通知，父会话据此继续下一轮** → 记录**父/子事件数增量**。
*验收*：真机（你在场），并有日志片段；"**主会话自动接着干**"那一步必须有**父会话日志里那条通知**作证据（不是靠我们面板上写一句话）。

*S5.6 授权*：`child.create`（建可续接子会话）/ `child.compact` / `child.prompt` 三步**各自单独点头**（见 `docs/06` §4）。

**S6 并存（G7）**
装上本插件后，`dsh-context@0.60.0` 的面板照常工作；控制台无 `already registered` / `loaded without registering` 报错。
*验收（必须可复现，不是"我没看见错"）*：同一 profile 同时启用两个插件 → **依次**打开两个面板，并各触发一次只读路由（`detail`）→ 保存 **`dsh web` 启动日志** 与 **浏览器 console 全量片段**，断言其中不含指定错误字符串。

**S7 工程质量**
`tsc --noEmit` exit 0；`vitest run --project edit --project channel` 全绿；每条护栏测试**反向验证会真红**（改坏实现 → 看它红 → 改回），并把这一步写进提交说明。
*验收*：命令输出原文 + 反向验证记录（`docs/05` §6 的四个具体例子）。

**S8 可回滚（G9）**
任一次已生效的 `apply` 都能回滚：界面提供"这条的版本历史"（原 `#A` → 当前 `#M`，以及中间的每一次替换）→ 选一个版本 → **生成一条新的替换**把内容恢复成那个版本 → 需二次确认。
*验收*：
- 路由级测试：连续两次替换后回滚，**纯函数断言**（自写 fold 等价物，edit lane 可跑，**不许用 live Session 的同步读 API**——已废弃的 `deriveMessages` 就是这一类，见 `AGENTS.md` §2.2 与 D6）看到的**逐字等于**第一次之前的原文；
- 界面：显示 `原 #A → #M → 回滚 #N` 的关系链，且**每一步都能指认 seq**；
- 边界：被遮蔽的**原始节点**仍不能直接作目标（平台拒），回滚的目标是**当前可见的替换体**（`docs/01` F7）。

**S9 主会话不膨胀（G10，可观测）**
一次派活周期内：主会话**不调用开发执行类工具**（bash/edit/write 等）；其事件数增量只来自**人的决策**与 `child.prompt`。
*验收*：真机记录派活前后的**父会话事件数**与**字节增量**，并逐条说明每一条增量是什么。
**取舍**：若 token 口径不可靠就**只用事件数/字节**，并**删掉"控制规模"这类口号**——不许留无法判定的自我表扬。

**S10 能力开关对成功标准的影响（M4.5 填表，**预先给出降级口径**）**
M4.5（`docs/04`）会把平台能力验成一组**布尔开关**（`sessionQuery` / `agents` / `fork` / `compaction` / `rollbackHistory`）。
开关为 false 时，**本节的 S 条按下面这一档解释**，并且界面上**不允许出现"开关为 false 但按钮还在"**：

| 开关 | 若为 false | 受影响的 S 条（届时按此改写并留 diff） |
|---|---|---|
| `sessionQuery` | 读路径退回 live Session → **只有 live 会话可读可编辑** | S1/S2/S8 加"冷会话只读"限定；`docs/03` 的编辑与版本历史收口到 live-only |
| `agents` | 拿不到父/子 Agent → **不做 fork / 派活 / 打断** | S5 整条改写为"引导用原生工具"；`docs/03` §7 的 #19/#23 改为"入口不存在" |
| `fork` | 没有 `fork` provider → **M5 整块不做** | S5 删除；`plan.next` 只保留"提交草稿 / 固定不变量"两步 |
| `compaction` | 没有压缩后端 → 只做体检与记录 | S5.4 改为"引导你在子会话执行 `/compact`"；`docs/03` R5.3 **不显示执行按钮** |
| `rollbackHistory` | 读不到被遮蔽正文（V8 失败）→ **版本历史只读/不可恢复** | S8 降级为"只显示关系链，不提供恢复"；`docs/03` §7 #15 改为只验 #16 的关闭态 |

## 4. 与图 2 那套"上下文装配"的边界

图 2（微信群截图）那份能力清单里，**同一份能力其实混了三件事**。我们把它们分开，只做前两件：

| 图 2 的条目 | 属于什么 | 我们怎么处置 |
|---|---|---|
| ① 拍快照 | **会话快照** | ✅ 做（G5，M5） |
| ③ 整体注入一个新会话 | **会话生命周期** | ✅ 做（G5，M5）——用平台原生 fork，而不是自己拼一个会话 |

## 6. 术语（评审时统一口径）

| 词 | 含义 |
|---|---|
| **surface** | 模型当前能看到的内容集合（宿主权威）；日志里的原文可能**不在** surface 上 |
| **遮蔽（redact / shadow）** | 追加一条 `surfaceOp:{op:'replace'}` 事件，把原文从 surface 上拿掉；**原文仍在日志里** |
| **草稿（draft）** | 我们自己的本地数据（不写会话）；「应用到会话」才生效 |
| **批注（annotate）** | 追加一条带「作废范围」的更正消息；**不遮蔽**原文，模型两者都看到 |
| **固定块（不变量，invariant）** | 逐字保存的一段人类正文（标签 + 正文 + 版本 + 作用域），用来判定"漂移"与重注入。界面按钮统一叫 **`钉住这一段`**（D7 已统一命名，旧称不再使用） |
| **轮次 / 步骤（turn / step）** | 宿主概念：一轮里若干步，每步一次模型请求 |
| **快照（freeze）** | 我们的一条**记录**：记录冻结点（最后一个 `turn/end`）、条目数、**人写备注**（不是"摘要"；插件不生成摘要）、在效固定块版本；平台层面的"冻结"由 fork 的**一次性种子**实现 |
| **子会话（child session）** | 用父会话**已完成轮次**做种子新开的会话；父会话其后新轮次**不会**进去。它是**真会话**（有自己的 id 与日志），但**不出现在左侧会话列表里**——导航入口是父会话页头的血缘目录（官方行为，`docs/01` F13.1） |
| **可续接子会话** | 长期存活、可反复收后续消息、可单独 Stop 的子会话（`startContinuable`）；**收工时由平台往父会话追加结算通知** → 主会话据此继续。**v1 默认用它**（`docs/06` §3.1） |
| **一次性子会话** | 只跑一次、以单个结果结算（`start`）；结果只回到调用方，**父会话不会被自动唤醒**（"模型自己用工具发起"那条路径除外） |
