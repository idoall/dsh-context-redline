# Context Redline v0.10.0 — supervised runs

<h3 id="cn-v0.10.0">锚定会话可以再选一层「督导运行」</h3>

- 插件版本：`0.10.0`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.9.5`。
- 新增**督导运行**：锚定会话在确认目标卡时，可以额外勾选一层自动推进：
  - 冻结：目标、验收标准、执行纪律、任务表在创建时冻结成 run 目录（`docs/guard/<run-id>/`），其中 `tasks.json` 是唯一事实源、`state.jsonl` 只追加、`TASKS.md` 是人读的那一页、`run.json` 记录挂载身份与镜像状态；
  - 每轮审计：在 `agent/turn-stopping` 里**插件自己**跑该任务的确定性探针（轻/重两档，**永远不由模型执行**），再由独立评估器按冻结目标卡判定；
  - 逐任务落盘：通过后只提交该任务声明的路径加台账，并打 tag `guard/<run-id>/<task>`；一个任务失败就停在该任务上，不会把整轮任务表一起推进；
  - 锚点每轮从台账重渲染：历史被压缩也不会与实际在跑的任务脱节。
- **严格模式（默认关闭）**：勾选并确认后，主会话越出当前任务 scope 的写入、以及一切 shell 类工具（含 `terminal_*`）都会被拒绝；不勾选时只记录不拦截。路径判定带 `realpath` 与大小写核对，工作区外写入、悬空软链、大小写变体的台账改写都会被拒。
- **回退**：任务阻塞时把补丁留作证据；回退会重开该任务、清理它与兄弟任务之间的残留，并在回退重写历史后推进该任务的基线，避免被已撤销的提交终身追责。
- **观察到的进度**：Context 页新增督导卡，显示进度 / 当前任务 / 阻塞原因 / 挂载失败 / 镜像 issue；回退是两段确认，切换会话会复位已武装状态。
- **可选**：独立 worktree、`gh`/`glab` 镜像（一次性 issue + 状态评论）、每 N 个任务一次的里程碑三审。
- 已知边界（写进 `docs/17-goal-supervisor-design.md`，不是隐藏项）：并行任务共享同一个 run worktree（per-task worktree 需要平台给子会话单独的 cwd，目前没有）；工作区内软链在严格模式下一律拒绝；没有 `doneOrder` 字段的旧台账在其回退会跨过兄弟检查点时选择拒绝并提示人工，而不是猜顺序。
- 自动化回归、构建与包检查不等于生产界面人工验收；本次未执行生产重启或安装。真机端到端（真实模型跑完整轮任务）尚未执行。

```sh
dsh plugin --profile web add dsh-context-redline@0.10.0
```

<h3 id="en-v0.10.0">Supervised runs for anchored conversations</h3>

- Plugin version: `0.10.0`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.9.5`.
- New **supervised run**: while confirming the goal card, an anchored conversation can opt into a layer that drives itself:
  - **Frozen at creation.** Goal, acceptance criteria, discipline and the task table freeze into a run directory (`docs/guard/<run-id>/`), where `tasks.json` is the only source of truth, `state.jsonl` is append-only, `TASKS.md` is the page a human reads and `run.json` carries the mount identity and mirror state.
  - **Audited every turn.** In an `agent/turn-stopping` listener the plugin runs the task's deterministic probes itself (light and heavy tiers; **the model never runs them**) and has an independent evaluator judge the task against the frozen card.
  - **Committed per task.** A passing task is committed with exactly its declared paths plus the ledger and tagged `guard/<run-id>/<task>`. A failing task stops on that task instead of advancing the whole table.
  - **Anchors re-rendered from the ledger every turn**, so a compacted history cannot drift from the task actually running.
- **Strict mode, off by default.** Only a confirmed strict run denies writes outside the running task's scope and every shell-shaped tool (including `terminal_*`); without it the run records and commits but denies nothing. Path checks resolve `realpath` and compare case, so an escape, a dangling symlink and a differently-cased ledger path are all refused.
- **Rollback.** A blocked task keeps its patch as evidence. Rolling back reopens that task, settles the residue between it and its siblings, and advances its base commit after history is rewritten — so a reverted commit is not held against the task forever.
- **Visible progress.** The Context tab gains a supervisor card with progress, the current task, a blocked reason, a mount failure and the mirror issue. Rollback is a two-step confirmation, and switching sessions resets the armed state.
- **Optional**: an isolated worktree, a `gh`/`glab` mirror (one issue plus status comments), and a three-reviewer milestone review every N tasks.
- Known boundaries are recorded in `docs/17-goal-supervisor-design.md` rather than implied: parallel tasks share one run worktree (per-task worktrees would need a per-delegation cwd the platform does not offer); a symlink inside the workspace is refused in strict mode; and a ledger written before `doneOrder` existed refuses a rollback that would cross a sibling checkpoint instead of guessing.
- Automated regression, build and package checks are not the same as human acceptance in a production UI. No production restart or install was performed, and a real end-to-end run (a real model completing a whole task table) has not been executed yet.
