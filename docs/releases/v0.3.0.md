# Context Redline v0.3.0 — runtime-rule anchor

<h3 id="cn-v0.3.0">新增：锚点的“每轮运行时规则”方式</h3>

- 插件版本：`0.3.0`。支持 DSH `>=0.2.2-rc.5 <0.3.0-0`，针对 `0.2.2-rc.5` 构建与回归验证；要求 Node.js `>=24.9.0`。旧版 DSH 可继续使用插件 `0.2.0`。
- 确认框的锚点新增两种生效方式：
  - **放在首条消息**（默认，0.2.0 行为）：开头与结尾各原样出现一次；
  - **每轮运行时规则**（新）：不写进首条消息，而是注册为承载会话的 DSH 运行时上下文。
- 运行时规则使用 `systemPrompt.context`（name `dsh-context-redline:anchor`、order `10000`、不插值、required），只作用于本插件创建的承载会话。DSH 的快照机制保证：文本不变时不会重复写入；会话压缩折叠后会自动重新声明，并明确说明取代早先版本（包括压缩摘要里的残留）。
- 该方式默认关闭，必须由人显式选择；锚点原文逐字出现在确认框，并写入台账（原文 + 指纹），恢复时按同一文本重新注册。空锚点不能选择运行时方式；改锚点或改方式都会使旧确认失效。
- 不是预设系统提示词，也不是工具定义；不调用模型、不摘要、不改写，来源会话保持 append-only。
- 保留 0.1.x / 0.2.0 的行为修复：读取会话当前模型与预设、等待异步投影注册并使用保留句柄、保留新版工具结果历史正文与错误状态。
- 同步中英文 README、CHANGELOG、支持范围与 npm 包内容；GitHub Release 仍等待 npm 发布成功后创建。
- 不包含未验收的体检功能、carrier-seed 实验或其他本地未发布改动。自动化回归、构建和包检查不等于生产界面 / 真实会话人工验收，本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.3.0
```

如安装结果提示需要重启，由用户本人重启 `dsh web`。

<h3 id="en-v0.3.0">New: per-request runtime-rule anchor</h3>

- Plugin version: `0.3.0`. Supports DSH `>=0.2.2-rc.5 <0.3.0-0`, built and regression-tested against `0.2.2-rc.5`; requires Node.js `>=24.9.0`. Older DSH users can stay on plugin `0.2.0`.
- The confirmation anchor now has two delivery modes:
  - **In the first message** (default, the 0.2.0 behavior): repeated verbatim at the start and end;
  - **Per-request runtime rule** (new): kept out of the first message and registered as a DSH runtime context for the carrier.
- The runtime rule uses `systemPrompt.context` (name `dsh-context-redline:anchor`, order `10000`, no interpolation, required) and applies only to the carrier this plugin creates. DSH's snapshot mechanism guarantees unchanged text is not rewritten, and after compaction folds the snapshot it is re-declared with an explicit notice that it replaces earlier versions, including retained conversation summaries.
- The mode is off by default and must be chosen by the human; the anchor text is shown verbatim in confirmation and frozen in the ledger (text plus fingerprint), so recovery re-registers the same text. An empty anchor cannot select runtime mode; changing the anchor or mode invalidates an old confirmation.
- It is not a preset system prompt or tool definition; no model call, summary or rewrite, and the source session stays append-only.
- Retains the 0.1.x / 0.2.0 fixes: current model/preset reads, asynchronous projection registration with the retained handle, and current tool-result history content and failure status.
- Synchronizes both READMEs, the changelog, the support range and npm package contents. The GitHub Release still waits for successful npm publication.
- Excludes unaccepted diagnostics, carrier-seed experiments and other unpublished local work. Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.3.0
```

If installation reports that a restart is required, restart `dsh web` yourself.
