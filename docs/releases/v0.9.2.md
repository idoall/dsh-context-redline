# Context Redline v0.9.2 — the guard block is always offered

<h3 id="cn-v0.9.2">交接卡每次都给出守卫段，勾不勾由你决定</h3>

- 插件版本：`0.9.2`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.9.1`。
- `context-redline-handoff` 不再等用户先说“要开守卫”：**每次都给**可选的「目标守卫」段，不勾选就直接忽略。技能只负责给全格式与提醒，不替用户做决定，也不催开启。
- 输出只是文字：**打印不等于启用**。守卫仍然只在确认框里勾选后创建，不勾选就零额外模型调用、零状态文件。
- 守卫段内容不变：可被独立评估器判定的任务清单（命令 / 文件 / 可观察结果）、计划文件（对话里没有明确路径就写“不填”）、评估模型（不编造 provider/model 名称）、以及 0.9.x 只观察的说明。
- 自动化回归、构建与包检查不等于生产界面或真实会话人工验收；本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.9.2
```

<h3 id="en-v0.9.2">The handoff card always offers the guard block</h3>

- Plugin version: `0.9.2`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.9.1`.
- `context-redline-handoff` no longer waits for an explicit “enable the guard” request: it **always** emits the optional guard block, and the user simply ignores it when they do not want the guard. The skill only supplies the format and the reminders; it does not decide for the user and does not push them to enable it.
- The output is only text: **printing it enables nothing**. The guard is still created only when the box is checked; unchecked means zero extra model calls and no state file.
- The block itself is unchanged: acceptance the independent evaluator can judge (commands / files / observable results), the plan-file choice (an explicit “leave it empty” when the conversation names no path), the evaluator choice (never inventing provider/model names), and the observe-only note.
- Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.9.2
```
