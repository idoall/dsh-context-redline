# Context Redline v0.8.4 — insecure-origin crash fix

<h3 id="cn-v0.8.4">修复普通 HTTP 部署下的崩溃：`crypto.randomUUID is not a function`</h3>

- 插件版本：`0.8.4`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.8.3`。
- 问题：`crypto.randomUUID` 只在安全上下文（HTTPS 或 `localhost`）存在。用 `http://<局域网IP>:<端口>`（例如 `http://10.0.0.30:3080`）打开 DSH 时，点开「上下文批改」页签会让锚定会话卡片在渲染阶段生成 operationId，于是抛 `crypto.randomUUID is not a function`，整块面板不可用。
- 修复：新增 `src/client/ids.ts`，id 生成按三级回退——`crypto.randomUUID` → `crypto.getRandomValues` → `Math.random`；三种路径都产出 RFC 4122 v4 形状，确认请求里的 operationId 仍是稳定 UUID，重复点击仍被固定 ID 台账拦住。
- 回归：`tests/client-logic/ids.spec.ts` 钉住三条路径与 v4 形状；`tests/client-ui/child-card.spec.ts` 在删除 `randomUUID` 的环境里渲染卡片、打开并确认锚定会话——旧实现会以用户看到的同一条错误失败，新实现通过。
- 不改宿主字段、模型调用、会话写入或来源会话；保留 0.8.3 的 DSH `0.2.3-alpha.2` 兼容性（章节式系统提示词按“幸存消息求和”计价）。
- 自动化回归、构建与包检查不等于生产界面或真实会话人工验收；本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.8.4
```

<h3 id="en-v0.8.4">Fix the crash on plain-HTTP deployments: `crypto.randomUUID is not a function`</h3>

- Plugin version: `0.8.4`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.8.3`.
- The problem: `crypto.randomUUID` exists only in a secure context (HTTPS or `localhost`). Opening DSH at `http://<lan-ip>:<port>` (for example `http://10.0.0.30:3080`) and clicking the Context Redline tab made the anchored-conversation card mint its operation id during render, throwing `crypto.randomUUID is not a function` and taking the whole panel down.
- The fix: a new `src/client/ids.ts` mints the id through three arms — `crypto.randomUUID` → `crypto.getRandomValues` → `Math.random`. All three produce the RFC 4122 v4 shape, the confirm request still carries a stable operation id, and the fixed-id ledger still blocks a repeated click.
- Regression: `tests/client-logic/ids.spec.ts` pins the three arms and the v4 shape; `tests/client-ui/child-card.spec.ts` renders the card, opens the anchored dialog and confirms with `randomUUID` removed — the old implementation fails with the exact error the user saw, the new one passes.
- No host field, model call, session write or source-session change; the 0.8.3 DSH `0.2.3-alpha.2` compatibility (section-era system prompt priced as the sum of its surviving messages) is retained.
- Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.8.4
```
