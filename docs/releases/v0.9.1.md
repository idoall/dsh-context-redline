# Context Redline v0.9.1 — the handoff skill emits the guard package

<h3 id="cn-v0.9.1">交接技能补全：勾选目标守卫时给出整段守卫内容</h3>

- 插件版本：`0.9.1`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.9.0`。
- `context-redline-handoff` 技能的**描述与触发条件**加入目标守卫：问「守卫怎么开 / 任务清单怎么写 / 评估模型选哪个 / 计划文件填什么」也会命中。
- 技能输出从「只给任务清单」升级为**整段守卫内容**（只在用户要启用守卫时给）：
  - **任务清单**：每行 `T1 | 标题 | 验收1；验收2`，每条验收写成**离开对话也能判定**的命令 / 文件 / 可观察结果——评估器只看冻结目标卡、当前任务和有界产出，看不到完整历史；
  - **计划文件**：对话里出现过明确路径才写，否则明确写“不填”并给理由，不编造路径；同时说明改了会被记为阻塞（0.9.0 只记录不阻断）；
  - **评估模型**：默认「跟随主会话」；要第二意见就说明“建议另选一个模型”，**不编造 provider/model 名称**；
  - **只观察提醒**：明确写“0.9.0 只观察，不拦工具、不 steer、不替用户结束轮次”，不做“会自动拦住”的承诺。
- 质量检查新增两条：验收能否被独立评估器判定；计划文件路径是否真的在对话里出现过。
- 守卫本身的行为不变：冻结目标卡、任务台账、每轮一次独立评估、守卫卡（判定 / 纠正 / 评估成本 / 暂停恢复），全部只观察。
- 自动化回归、构建与包检查不等于生产界面或真实会话人工验收；本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.9.1
```

<h3 id="en-v0.9.1">Handoff skill completed: it now emits the whole guard package</h3>

- Plugin version: `0.9.1`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.9.0`.
- The `context-redline-handoff` skill now mentions the Goal Guard in its **description and trigger**: asking how to enable the guard, how to write the task list, which evaluator to pick, or what to put in the plan-file field will reach it.
- Its output grew from “a task list” to the **whole guard package** (only when the user plans to enable the guard):
  - **Task list**: one `T1 | title | acceptance;acceptance` per line, with every acceptance written as a command, file or observable result that the **independent evaluator can judge without the conversation** — it only sees the frozen card, the current task and a bounded excerpt;
  - **Plan file**: only when the conversation names a real path; otherwise an explicit “leave it empty” with a reason — never an invented path — plus the note that a change is recorded as blocked (0.9.0 records, never blocks);
  - **Evaluator**: “follow the main session” by default; for a second opinion it says “pick another model in the dialog” and **never invents provider/model names**;
  - **Observe-only reminder**: it states that 0.9.0 observes without blocking tools, steering, or ending turns, and never promises that something will be blocked.
- The quality checklist gained two questions: can the evaluator judge each acceptance, and does the plan-file path really appear in the conversation?
- Guard behaviour is unchanged: frozen goal card, task ledger, one independent evaluation per turn, guard card (verdict / correction / cost / pause-resume) — all observe-only.
- Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.9.1
```
