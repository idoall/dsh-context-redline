# Context Redline v0.4.1 — anchored-conversation reliability

<h3 id="cn-v0.4.1">修复：prompt-not-persisted 假阴性 + 弹窗底栏间距</h3>

- 插件版本：`0.4.1`。支持 DSH `>=0.2.2-rc.5 <0.3.0-0`，针对 `0.2.2-rc.5` 构建与回归验证；要求 Node.js `>=24.9.0`。旧版 DSH 可继续使用插件 `0.4.0`。
- 修复锚定会话首次创建时报 `anchor start held: prompt-not-persisted`：flush 已确认写入，但查询投影可能短暂滞后。宿主现在有界重读（3 次、200/500/1000ms 退避，最多约 1.7 秒），真实 request ID/正文冲突仍立即停止。
- 补齐锚定会话弹窗底栏间距：底栏 flex、按钮间 10px，说明文字与按钮之间留出空隙。
- 首条消息字节、运行时快照、`operationId` 幂等与回程语义均不变；没有模型调用。
- 自动化回归、构建和包检查不等于生产界面 / 真实会话人工验收，本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.4.1
```

<h3 id="en-v0.4.1">Fix: prompt-not-persisted false negative + dialog footer spacing</h3>

- Plugin version: `0.4.1`. Supports DSH `>=0.2.2-rc.5 <0.3.0-0`, built and regression-tested against `0.2.2-rc.5`; requires Node.js `>=24.9.0`. Older DSH users can stay on plugin `0.4.0`.
- Fixes `anchor start held: prompt-not-persisted` on first creation: flush confirms the append, but the query projection can lag briefly. The Host now re-reads a bounded number of times (3 retries, 200/500/1000 ms backoff, ~1.7 s worst case); a real request-id/content conflict still stops immediately.
- Restores the anchored-conversation dialog footer spacing: flex layout, 10 px between actions, and a gap between the scope copy and the buttons.
- First-message bytes, the runtime snapshot, `operationId` idempotency and return semantics are unchanged; no model call is added.
- Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.4.1
```
