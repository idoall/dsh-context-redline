# Context Redline v0.9.4 — the handoff card stops asking for per-task approval

<h3 id="cn-v0.9.4">交接卡不再逐任务要你点头</h3>

- 插件版本：`0.9.4`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.9.3`。
- 问题：交接卡把「主会话审查」和「用户批准」写成了同一件事——执行纪律原来要求「每个任务结束停下汇报，用户明确『通过』才进入下一个」。一个 6 任务的卡片就变成 6 次打断。真实会话（`session-anchor-c3075660…`）就是在 T1 完成后停下来问「T1 是否通过」。
- 修复：把两件事分开写——
  - 主会话对照验收**审查通过后直接继续下一个任务**，不再逐任务等用户批准；
  - 每完成一个**里程碑**汇报一次；你明确说「过程中不用确认 / 一路做到底」时，改为**全部完成后汇报一次**；
  - 只有四种情况**必须**停下来问：目标或验收需要改；实测前提被打破（环境不可用 / 许可缺失 / 需要你本人操作）；不可逆或外部副作用；安全或合规冲突。
- 纪律第 3 条同步改写（原来写「只取消逐里程碑确认」，与逐任务批准矛盾），验收写法与质量检查新增「不得把审查写成逐任务批准」。
- 只改技能文本：目标守卫（只观察）、计价、数据写入都没有变化。
- 自动化回归、构建与包检查不等于生产界面人工验收；本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.9.4
```

<h3 id="en-v0.9.4">The handoff card no longer asks for approval after every task</h3>

- Plugin version: `0.9.4`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.9.3`.
- Problem: the handoff card wrote “the main session reviews a task” and “the user approves a task” as one rule — the discipline demanded a stop after every task and an explicit user “pass” before moving on. A six-task card therefore meant six interruptions; a real session stopped right after T1 to ask whether T1 passed.
- Fix: the two are separated —
  - the main session checks the acceptance, passes the task and **moves straight on**; no per-task user approval;
  - one report per **milestone**; when you explicitly say “no confirmation during the process / run to the end”, the single report moves to the very end;
  - only four situations **must** stop: goal or acceptance has to change; a measured premise broke (environment unavailable, missing licence, user action required); an irreversible or external side effect; a safety or compliance conflict.
- Discipline item 3 was rewritten (it used to say “only milestone confirmation is cancelled”, contradicting the per-task gate), and the acceptance guidance plus the quality checklist now reject a card that turns review into per-task approval.
- Skill text only: guard behaviour (observe-only), accounting and data writes are unchanged.
- Automated regression, build and package checks are not production visual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.9.4
```
