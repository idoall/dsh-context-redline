# Context Redline v0.9.0 — Goal Guard (observe-only beta)

<h3 id="cn-v0.9.0">目标守卫 0.9.0：锚定会话的只观察审计</h3>

- 插件版本：`0.9.0`。支持 DSH `>=0.2.3-alpha.2 <0.3.0-0`，针对 `0.2.3-alpha.2` 构建与回归验证；要求 Node.js `^24.22.3 || >=26.13.1`。旧版 DSH 可继续使用插件 `0.8.4`。
- 新增**目标守卫（Beta，只观察）**，只在新建锚定会话时可选开启：
  - **目标卡 hash**：目标 / 验收 / 纪律 / 任务清单（可选再带计划文件）在创建时冻结成一个 hash，评估器必须回显同一 hash，对不上就判定 `blocked`；
  - **任务台账**：每行 `T1 | 标题 | 验收1；验收2`，盯住任务状态、尝试次数和最后一次审计的证据摘要；
  - **独立评估器**：每轮结束一次独立模型调用（可选另一个 provider/model，30 秒超时、temperature 0、只收 JSON），只看冻结目标卡、当前任务和该任务开始后的有界产出片段——不看完整会话历史；判定 `pass` / `fail` / `insufficient` / `blocked`，并记录评估模型、耗时和 token；
  - **计划文件**：创建前读取并预览章节标题，hash 与目标卡一起冻结，每轮审计前重新校验，被改或读不到记为 `blocked`；
  - **守卫状态卡**：进度、当前任务、最近判定、纠正建议、暂停 / 恢复。
- **0.9.0 严格只观察**：不拦截工具、不 steer 会话、不结束轮次；计划文件变更也只记录不阻断。拦截路径（工具守卫、回合收尾拦截、尝试 / steer 上限、最终总审计）已在代码中，留待下一版显式开启。
- 失败语义是「不敢说通过」：评估模型不可用、调用失败、返回不可解析、或该任务没有可审计产出，一律 `insufficient`，绝不 `pass`。
- 守卫状态只写 `$DSH_HOME/dsh-context-redline/guard/<sessionId>.json`；不写来源会话日志、不改预设系统提示词或工具定义、不注册模型工具，没有守卫状态的会话完全不受影响。
- 自动化回归、构建与包检查不等于生产界面或真实会话人工验收；本次未执行生产重启或安装。

```sh
dsh plugin --profile web add dsh-context-redline@0.9.0
```

<h3 id="en-v0.9.0">Goal Guard 0.9.0: an observe-only audit for anchored conversations</h3>

- Plugin version: `0.9.0`. Supports DSH `>=0.2.3-alpha.2 <0.3.0-0`, built and regression-tested against `0.2.3-alpha.2`; requires Node.js `^24.22.3 || >=26.13.1`. Older DSH users can stay on plugin `0.8.4`.
- Adds an opt-in **Goal Guard (beta, observe only)** that is enabled when you create an anchored conversation:
  - **Frozen goal card**: goal, acceptance, discipline and the task list (optionally a plan file) are frozen into one hash; the evaluator must echo that hash or the verdict becomes `blocked`;
  - **Task ledger**: one task per line, `T1 | title | acceptance;acceptance`, with status, attempt count and the evidence captured by the last audit;
  - **Independent evaluator**: one separate model call per turn (optionally on another provider/model, 30s timeout, temperature 0, JSON only) that sees only the frozen card, the current task and a bounded excerpt of what the session produced since that task started — never the full history. Verdicts are `pass` / `fail` / `insufficient` / `blocked`, recorded with the evaluator model, latency and tokens;
  - **Plan file**: read and previewed before creation, its hash frozen with the goal card and re-checked before each audit; a changed or unreadable file records `blocked`;
  - **Guard card**: progress, current task, latest verdict, correction suggestion, and pause/resume.
- **0.9.0 is strictly observational**: it never blocks a tool, never steers the session, never ends a turn, and a changed plan file is recorded without stopping anything. The blocking path (tool guard, turn-stopping audit, attempt/steer caps, final audit) stays in the code for an explicit later version.
- Failure means "not proven": an unavailable evaluator, a failed or unparseable call, or a task with no auditable output is `insufficient`, never `pass`.
- Guard state lives only under `$DSH_HOME/dsh-context-redline/guard/<sessionId>.json`; the source session is never rewritten, no preset system prompt or tool definition is touched, no model tool is registered, and a session without a guard is completely unaffected.
- Automated regression, build and package checks are not production visual or real-session manual acceptance. No production restart or installation was performed.

```sh
dsh plugin --profile web add dsh-context-redline@0.9.0
```
