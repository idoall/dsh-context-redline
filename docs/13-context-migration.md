# 上下文迁移合同

## 目标

迁移器从来源会话的一次稳定 surface 读取中构造候选材料，经本地编辑 / 删除决定生成清单，再序列化为零历史普通会话的第一条用户消息。

来源会话日志永不改写。删除表示该来源身份不进入 delivery set。

## 来源身份

事件材料使用完整身份：

```text
event:<sourceSessionId>:<seq>:<eventType>
```

身份不能由正文推断。跨会话相同 seq、相同正文的不同事件都必须保持独立。

每次捕获记录完整来源 session ID、`capturedThroughSeq`、完整 surface 指纹，以及候选的稳定顺序、原角色、全文、可公开 reasoning、错误状态与工具调用配对。

确认前来源版本或草稿版本变化，会使旧确认失效。

## 可迁移角色

| 来源 | 迁移方式 |
|---|---|
| user | 普通迁移文本，标明原角色 |
| inject / skill | 普通迁移文本，明确它不是目标会话系统层 |
| assistant | 编辑迁移副本；旧 assistant/message 不变 |
| tool result | 必须匹配 call ID、工具名与参数摘要，并保留 `isError=true/false` |
| system material | 只可作为有来源标签的普通迁移材料；不冒充目标系统提示词 |
| tool schema | 不作为可编辑迁移正文；由目标预设生成 |

孤立工具结果会拒绝迁移。

## 图片和附件

- `image` 块不复制到新会话。
- 混合文字 / 图片消息继续迁移全部文字，并累计遗漏图片数。
- 纯图片消息不生成空白候选，但累计遗漏图片数。
- 确认框必须显示「图片 N 个未迁移」。
- surface 指纹仍覆盖完整原始事件，包括图片附件身份；图片变化会使旧确认失效。
- `file`、`file-ref`、`attachment` 和未知富媒体仍拒绝。

这保证“暂不迁移图片”不会退化成静默丢数据，也不会让一张图片阻断整次文字迁移。

## 决策清单与投递集合

一次纯函数计算同时产出：

1. **decision manifest**：所有候选及其 `keep | edited | deleted | trimmed` 动作；
2. **delivery set**：只含 `keep | edited`。

优先级：

```text
用户删除 > 用户明确保留 > 用户编辑 > 自动裁剪
```

删除标记和编辑正文独立保存。已编辑再删除时，编辑正文留在 decision manifest；取消删除后原样恢复。

## 最终发送全文

manifest 先生成默认文本：

```text
<用户任务>

<迁移说明>

【来源身份 / 原角色】
<完整正文>
```

确认框中的“最终发送全文”随后成为权威值。用户可以删段、改字或重排。

确认时必须冻结：

- `deliveryContent` 和内容指纹；
- 来源 / manifest 指纹；
- 工作区与 cwd；
- 目标 preset / provider / model / reasoning effort；
- 来源会话回程恢复配置；
- 附件引用集合（当前必须为空）。

未编辑最终文本时，默认 manifest 文本与实际投递逐字一致；编辑后，确认框文本、`executionInput.deliveryContent`、实际 followup 和恢复重放必须逐字一致。

## 不允许的行为

- 使用列表预览代替全文；
- 按正文字符串删除材料；
- 静默截断；
- 将删除项放回投递正文并附“不要采用”说明；
- 把迁移材料表示成目标会话真实系统提示词或工具定义；
- 恢复时重新读取当前草稿并组装另一份输入；
- 静默丢弃文件、未知媒体或孤立工具结果。

## 关键验证

- 相同正文、不同身份互不影响；
- 跨会话相同 seq 互不影响；
- 删除项留在 decision manifest，但不在 delivery set；
- reasoning 和工具 `isError` 进入正文与指纹；
- 混合文字 / 图片保留文字并计遗漏；
- 纯图片不生成空段；
- 图片引用变化改变来源指纹；
- 文件 / 通用附件继续拒绝；
- 最终文本和实际投递逐字一致；
- 损坏的冻结正文、配置或身份在恢复时拒绝执行。
