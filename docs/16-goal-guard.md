# 目标守卫（0.9.0，Beta，只观察）

目标守卫是**按会话、默认关闭**的审计回路：它把锚定会话的目标卡冻结下来，每轮结束后用一次**独立模型调用**判断「当前任务是否按冻结的目标做完了」，把判定和纠正建议写进一张守卫状态卡。

**0.9.0 只观察**：不拦截工具、不 steer 会话、不结束轮次。拦截路径（工具守卫、回合收尾拦截、尝试 / steer 上限、最终总审计）已经在代码里，但只有显式 `dryRun: false` 才会启用，而当前插件通道不会转发这个值——它留给下一版。

## 怎么开启

只在**新建锚定会话**的确认框里开启（`目标守卫（Beta · 只观察）`）：

1. 目标 / 验收 / 纪律（这三项锚定会话本来就要填）；
2. **任务清单**：每行一个任务，格式 `T1 | 标题 | 验收1；验收2`；
3. （可选）**评估模型**：不选就跟随主会话；选另一个 provider/model 相当于要第二意见；
4. （可选）**计划文件**：相对当前工作区的路径，创建前会读取并预览章节标题，hash 与目标卡一起冻结。

守卫只对这一次创建出来的会话生效。没开启的会话不会挂任何运行时上下文、工具守卫或回合监听。

## 目标卡与 hash

目标卡由目标、验收、纪律、任务清单和（可选）计划文件 hash 规范化后算成一个 `goalHash`：

- 评估器每次都必须回显同一个 hash；对不上时判定为 `blocked`（dry-run 只记录，不阻塞），因为这说明目标卡被改过或评估器看错了目标；
- 计划文件在每轮审计前重新读取并比对 hash：文件被改或读不到，同样记为 `blocked`，提示先让人确认新目标；
- 目标卡只在创建时冻结，创建后不做任何修改；想改目标只能重新开会话。

## 任务台账

任务状态：待办 / 进行中 / 通过 / 失败 / 阻塞。每条任务带验收项、尝试次数、开始 seq 和最后一次审计的证据摘要（最近一条助手产出的前 300 字 + 最近 5 条工具名）。台账写在插件数据目录，不写会话日志。

## 独立评估器

每次审计是**单独一次模型调用**（`llm.prepareCall`，30 秒超时，temperature 0，最多 2500 输出 token），它看不到主会话历史，只收到一段 JSON：

- 冻结目标卡：hash、目标、验收、纪律；
- 当前任务：id、标题、验收项；
- 候选产出（有界）：该任务开始 seq 之后最近的 4 条助手正文（累计最多 4000 字）、最近 20 个工具名、主会话直接写/执行计数、子会话调用数。

它必须只输出 JSON：`{goal_hash, verdict, criteria[], violations[], missing[], correction, next_action}`，`verdict` 取 `pass` / `fail` / `insufficient` / `blocked`。

失败语义是「不敢说通过」：

- 评估模型不可用、调用失败、返回不可解析 → `insufficient`，不是 `pass`；
- 该任务开始后没有任何助手产出 → `insufficient`；
- 判定结果和评估模型 / 耗时 / token 一起记在守卫状态卡上，便于核对成本。

## 只观察（0.9.0 的实际行为）

- 不拦截任何工具调用：主会话直接写文件、跑命令都不会被拒绝；
- 不 steer 会话：判定和纠正建议只出现在守卫卡上，不会发回模型；
- 不结束轮次：回合收尾审计只记录，不阻塞；
- 计划文件变更只记录为 `blocked` 判定，不阻断会话；
- 暂停只改守卫状态文件（`paused`），不碰会话日志。

拦截版（工具守卫拒绝主会话写/执行、未全部通过不允许 `update_goal complete`、最多 3 次尝试 / 12 次 steer 后 marked blocked、全部任务通过后做一次最终总审计）留待下一版显式开启。

## 搭配交接技能

`context-redline-handoff` 技能每次都会给出整段守卫内容（可选，不勾选就忽略）：任务清单（每条验收写成评估器离开历史也能判定的命令 / 文件 / 可观察结果）、计划文件路径（对话里没有明确路径就写“不填”）、评估模型建议（默认跟随主会话，不编造 provider/model 名称），并提醒 0.9.x 只观察、不拦工具、不 steer。它同时把「主会话审查」与「用户批准」分开写：审查通过就直接继续下一个任务，只有里程碑 / 全部完成、以及四种前提破裂（目标变更、前提被打破、不可逆副作用、安全合规）时才停下来问人。输出只是文字，不会因为打印而启用守卫；守卫仍只在勾选后创建。

## 守卫状态卡

锚定会话页的「上下文批改」面板里、承载会话卡下方：

- 进度：已通过 N / 总数；
- 当前任务；
- 最近判定与纠正建议；
- 评估模型 · 耗时 · 输入 / 输出 token；
- 暂停 / 恢复按钮（只作用于守卫）。

## 存储与故障语义

- 位置：`$DSH_HOME/dsh-context-redline/guard/<sessionId>.json`；
- 读不到、JSON 损坏、会话 id 不符或任务为空 → 视为没有守卫（不会崩、不会假装有守卫）；
- 暂停 / 恢复会写回状态文件；写失败只影响本次暂停，不影响会话本身。

## 边界

- 不写来源会话日志，不读主会话历史给评估器；
- 不改预设系统提示词或工具定义，不注册任何模型工具；
- 守卫的运行时上下文只注册在那个会话的 Agent 上，随它一起卸载；
- 没有守卫状态的会话完全不受影响。

## 0.9.0 未包含

- 拦截开关（严格模式）——代码已实现，界面与服务通道尚未开放；
- 双评估交叉验证、Autopilot 自动推进；
- 证据归档与跨会话成本汇总。

这些都不属于 0.9.0 的承诺；是否要做、怎么做，等观察版在真实会话里跑过一轮再定。
