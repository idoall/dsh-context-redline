# 上下文批改：用户指南

## 这是什么

「上下文批改」让你查看当前会话中模型实际可见的上下文，并在不改动来源日志的前提下准备一份迁移副本。确认后，插件在当前工作区创建一个零历史普通会话执行任务，并把绑定结果原样送回来源会话。

## 基本流程

1. 打开会话中的「上下文批改」。
2. 查看某一轮 / 某一步的上下文。
3. 可选：逐条编辑或删除材料。保存只写插件本地。
4. 点击「开启普通新会话」。
5. 填写任务，并直接修改「最终发送全文」。
6. 选择执行模型；推理等级可保持「使用模型默认值」。
7. 确认创建。
8. 在左侧会话列表打开新会话；任务完成后，结果会自动回到来源会话。

## 哪些内容可以编辑

| 类型 | 能否编辑迁移副本 | 说明 |
|---|---:|---|
| 用户消息 | 可以 | 来源日志不变 |
| 注入内容 | 可以 | 编辑的是本次迁移副本 |
| 技能材料 | 可以 | 编辑的是本次迁移副本 |
| 助手消息 | 可以 | 不改写历史 assistant/message |
| 工具结果 | 可以 | 需要匹配原工具调用；入口位于高级编辑 |
| 系统提示词 | 不可以 | 由目标预设生成 |
| 工具定义 | 不可以 | 由目标预设和平台生成 |

被遮蔽或已经离开当前 surface 的条目也不可编辑。

## 本地编辑与删除

- `保存`：只写 `$DSH_HOME/dsh-context-redline/`，当前会话模型看不到。
- `丢弃这条改动`：清除本地编辑，恢复来源全文。
- `删除`：表示不迁移该条；来源日志不变。
- `取消删除`：恢复该条参与迁移。
- 编辑正文和删除标记独立保存，因此“编辑 → 删除 → 取消删除”会恢复编辑稿。

## 最终发送全文

确认框会把迁移材料序列化为一个完整用户消息。文本框里的内容就是新会话实际收到的第一句话：

- 可直接删段、改字或重排；
- 确认后逐字冻结；
- 崩溃恢复只重放冻结内容，不重新拼接当前草稿；
- 空文本不能创建。

文本框默认约六行，长内容在框内滚动，也可手动向下放大。

## 不知道填什么：执行交接技能

插件自带一个运行时技能 `context-redline-handoff`。在对话里说“用 context-redline-handoff 技能”，或从技能列表选择它，它会：

1. 读当前对话，找出最初目标、已完成/已验收、当前阻塞和完成标志；
2. 推荐用「新建带规则的对话」还是「开启普通新会话」迁移；
3. 按场景输出：
   - **情况 A（迁移）**：首条任务 + 锚点（选「每轮运行时规则」），最终发送全文由插件自动拼接；
   - **情况 B（不迁移）**：首条任务 / 目标 / 验收标准 / 执行纪律四段；
4. 在纪律里带上：**先拆任务（每个里程碑/交付物一个任务，每任务至少一个子会话）**、主会话只规划/分派/审查、不得单会话连续做多个里程碑、即使你说“过程中不用确认”拆分与审查也不取消、UI 改动必须有头 UAT 到无问题、出错修正并继续、每个任务/里程碑停下等用户验收、每轮先读计划文件、不扩范围、证据必须真实。
5. 判断这次是否涉及 UI：涉及则验收里要有有头 UAT 的复测证据；不涉及则写“无需 UAT”及理由。验收还必须包含任务清单、每个任务的子会话产物与主会话审查记录。

把对应字段粘贴到弹窗即可。技能不会自己建会话、不会写文件，也不会替你改目标。

## 不迁移上下文：锚定会话

如果这次只是想让一个新对话“目标别丢”，不需要搬当前上下文：

1. 打开任意已聊过的会话，进入「上下文批改」。
2. 点「新建带规则的对话」。
3. 填写：
   - **首条任务**：新对话的第一句话；
   - **目标**：默认跟随首条任务，可直接改；
   - **验收标准**：什么算完成；
   - **执行纪律**：例如“出错时修正并重新验证，继续原目标；不得因出错改目标”。
4. 确认前可看到**实际注册的快照全文**；创建后冻结。
5. 创建成功后会自动进入这个新对话。

它不迁移上下文、不设置回程，也不改 DSH 原生「新建对话」。快照在每次请求中可见，文本不变不重复写入，压缩后会由 DSH 自动重新声明。

## 督导运行（Beta）

只在新建锚定会话时可选开启，默认关闭。开启后：

1. 在任务表里每行写一个任务（四列，scope 必填）：`T1 | 标题 | 验收1；验收2 | src/a.ts,src/b.ts`；
2. 可选填写探针命令：`T1 | pnpm test`（插件按空白切分直接执行，不经过 shell，退出码 0 才算通过）；
3. 模型有四条链，按「评估对 → 执行对」排列，都可单独选推理等级（留空即「使用模型默认值」）：**独立评估模型**（默认跟随主会话，也可同一模型降等级）、**评估回退模型**（评估返回空文本/超时/限流时切换；留空则评估失败按 insufficient 处理——任务卡住，但不会误判通过）、**对话执行模型**（新会话与它派出的子会话实际执行任务的模型；勾选督导运行后它出现在本选项区、紧挨「执行回退模型」之前；未勾选时在下方运行配置里）、**执行回退模型**（主执行模型不可用时自动切换；留空只提示不切换）。回退只有跨 provider 才有意义：同一 provider 的额度、鉴权类错误切了也没用。评估调用不设人为输出上限，用的是模型自己的默认预算（和正常对话一致）；如果仍返回 `MAX_TOKENS`，说明撞到了该模型自身的输出上限——换模型或把等级降到 High，插件会把修法写在阻断原因里；
4. 验收含截图 / UI / 渲染类证据时，勾选 **启用视觉取证** 并给 witness 选一个声明支持图片输入的多模态模型（留空跟随评估模型；评估模型是纯文本时会得到 UNSUPPORTED_CONTENT）。witness 只列问题、不给结论，裁决仍由文本评估器做；插件对「验收需要视觉但没拿到 witness」是确定性否决，纯后端 / 文档任务不要勾。
5. 可选勾选「严格模式」（拒绝主会话 scope 外写入与一切 shell 工具）或「在独立 worktree 中运行」（在当前工作区的 `.guard/worktrees/<runId>` 建隔离检出与 `guard/<runId>` 分支；该目录写进 `.git/info/exclude` 本地忽略、不会进提交，也**不会新建 DSH 工作区**——会话仍归当前工作区的侧栏分组，只有运行目录切到隔离检出；提交不会自动合回，完成后手动 merge）。**对话框会先读一次仓库事实（只读）：检测到 git 仓库时自动勾上「独立 worktree」**（GitLab/GitHub 远端会在提示里点名），你仍可取消；若取消时正停在默认分支（`main`/`master`），会提示督导提交会直接落在该分支。
6. 确认框会显示只读的**运行目录**：新会话就在这里运行，探针与任务 scope 的相对路径都以它为根。要改另一个仓库，请先切到那个工作区再开会话——在 A 仓的交接卡里写 B 仓的路径，第一次探针就会失败。

运行台账落在仓库的 `docs/guard/<runId>/`（`tasks.json` 唯一事实源、`state.jsonl` 追加审计日志、`TASKS.md` 人类可读视图）。每轮结束插件先跑探针、再由独立评估器结合探针结果、scope 内 diff 与 `notes.md` 判定，通过后自动只提交该任务声明的路径加台账并打 tag `guard/<runId>/<task>`；阻塞时自动停下并保留补丁，可在「上下文批改」面板下方的督导卡双击确认回退。

**长跑与空转**：插件建 goal 时自带大轮次预算（默认 2000，按任务数放大），在仍有进展且余量见底时自动 `goals.edit` 续期，所以不会撞上宿主 256 轮的默认上限。反过来，必选探针已全过、但连续 5 轮既无 scope 内改动也没有新增「## 完成声明」的任务会被判为空转并自动置为阻塞，阻断原因里直接给出 `docs/guard/<runId>/tasks/<ID>/notes.md` 的路径——写完成声明是这个机制里唯一由主会话写台账的例外。

**卡片上的状态**：卡片同时读台账和宿主 goal。宿主目标因轮次上限被停、被暂停或未激活时，台账可能仍是 `active`，此时卡片显示「已阻塞/已暂停」并给出「继续运行」；点它会先扩容轮次再恢复目标。

## 锚点（可选）

确认框里除了「首条任务」，还有一个可选的「锚点」。它适合写一小段**你自己**的关键词或硬约束，例如：

- 必须用 TypeScript，不要改公开接口；
- 先跑测试再报告结果；
- 只改 `src/settings/` 下的文件。

锚点有两种生效方式：

1. **放在首条消息**（默认）：原样放在首条消息的**开头**（任务之后）和**结尾**（迁移内容之后）各一次。
2. **每轮运行时规则**：不写进首条消息，而是作为 DSH 的运行时上下文，只提供给这个承载会话。文本不变时不会重复写入；会话压缩后会自动重新声明，并说明它取代了早先的版本。

两种方式都由你显式选择，锚点原文会出现在确认框和确认指纹里；改了锚点或生效方式，旧确认会失效。边界（重要）：

- 锚点是用户写的原文，插件不调用模型、不摘要、不改写；
- 不会进入预设的系统提示词或工具定义，也不会改写来源会话；
- 留空时，首条消息与没有锚点时完全相同。

## 模型与推理等级

模型与推理等级位于同一行紧凑选择器中：

- 模型默认沿用来源会话；
- 推理等级默认使用该模型的系统默认值；
- 更换模型会把推理等级重置为模型默认值；
- 选择只影响新会话，不修改来源会话或全局默认；
- 宿主在创建前解析并冻结模型实际默认推理等级，再核对新 Agent 的实际配置。

## 图片和附件

- 文字与图片混合的消息：迁移全部文字，确认框显示「图片 N 个未迁移」。
- 纯图片消息：不生成空白迁移段，但计入遗漏数。
- 图片引用仍参与来源指纹；图片变化后旧确认失效。
- 图片二进制、文件、file-ref 和通用附件目前不迁移。
- 文件类或未知富媒体会明确拒绝，不会静默丢失。

## 什么时候不能创建

创建会被拒绝并显示原因，例如：

- 来源会话不在当前进程；
- 当前轮次尚未闭合；
- 来源或草稿在确认前发生变化；
- 工具结果无法匹配原调用；
- 目标模型或推理等级不可用；
- 工作区、预设或实际 Agent 配置无法核实；
- 台账损坏或冻结内容指纹不匹配。

错误不会自动重试创建，输入会保留。

## 自动回程

插件只取与本次固定 prompt request ID 绑定的任务结果。回程消息形如：

```text
【承载会话结果 · <标题> · <完整会话 id>】
<原样结果>
```

平台原始 `followup` 不提供 request ID 去重，因此插件还会核对精确正文、flush 后的冷日志和持久台账。查询结果为未知时不会盲目重发。

## 常见问题

**保存后，为什么当前模型仍看到旧内容？**
保存只在插件本地。只有确认创建新会话后，迁移副本才进入新会话。

**删除会清除原会话记录吗？**
不会。删除只表示“不迁移这条”。

**为什么图片没有进入新会话？**
当前版本只迁移同一消息中的文字，并明确报告遗漏图片数量。图片二进制迁移尚未实现。

**可以改来源会话的模型吗？**
不会。确认框的选择只配置新会话。

## 主/回退模型、继续运行与视觉取证（0.10）

- **执行模型 / 评估模型各有一条链**：主模型不可用时用「回退模型」，两者都可以单独选推理等级（评估在“跟随主会话”时也能选，等于同模型不同推理）。
- **什么时候换模型**：评估器遇到空回复（`EMPTY_RESPONSE`）、超时、限流、传输/服务端错误时会切到回退模型，并在台账写 `eval.fallback`；额度、鉴权、模型不存在这类问题只报清楚不盲换（跨 provider 的额度不足除外）。
- **运行被阻塞时**：卡片给出「继续运行」「换执行回退模型并继续」「换评估回退模型并继续」。继续只清阻断，**不重开任务、不丢 `baseCommit`**；换模型会写 `executor.switched` / `evaluator.switched`。
- **视觉取证（默认关闭）**：勾选后，插件把本任务相对 `baseCommit` 新增/修改的截图（最多 5 张、单图 ≤1 MiB）交给视觉模型做“观察”，只产出 findings（条目、严重度、现象、位置），**不给结论**；裁决仍由文本评估器做。witness 不可用（无截图、模型空回复等）时，视觉类验收最多判 `insufficient`，绝不可能因此通过。
- **CLI 桥接型 provider**（如 `antigravity`）适合当执行模型，但作为一次性评估器更容易返回空文本；对话框在评估选中它时会给出警告，建议改用文本模型。
