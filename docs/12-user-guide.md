# 12 · 用户帮助（「上下文批改」是什么、怎么用）

> 这份文档是**给用户看的**，不是给实现者看的。它同时是界面里那些 `?` 和不可用状态背后那句
> 「这一态是什么意思 / 我该怎么办」的**权威来源**（实现侧对应 `docs/03` 的 R4.7 与 R7.1）。
>
> 每条都标了对应的需求编号（R 编号见 `docs/03-ui-spec.md`），便于对照与验收。
> **规则**：这里**不出现未解释的内部术语** —— 凡是实现里的名字（投影、surface、seq、轮次边界…）
> 第一次出现时都用一句话讲清楚它对你意味着什么。

---

## 1. 这是什么（R0 / R7.1）

**上下文批改**给你一个能**动手改**的上下文浏览器。原来你只能看着模型读到的内容发呆：某句话写错了、
某段注入的内容每轮都在漂、某个工具结果里混进了不该有的东西 —— 你没法改，只能重新说一遍碰运气。

现在你可以：

1. **看**清楚这一次请求里模型到底读到了什么（按 7 类分，逐条列出，能看到全文）；
2. **改**其中的某一条，**保存**；
3. 需要的时候**开启子会话**，把改好的内容**逐字**带进那个新会话的第一句话，然后用改好的上下文继续干活。

⚠️ **最重要的一条**：**保存不会改到当前会话**。你在界面上改的东西只存在插件自己这里
（一个本地文件），**当前会话的模型看不到它**。只有当你**开启子会话**时，改后的正文才会被写进
那个新会话。这条是产品的地基，不是"以后会改"的临时限制。

---

## 2. 五分钟上手（R1 / R2 / R3）

| 你想做的事 | 怎么做 | 会发生什么 |
|---|---|---|
| 看某一轮/某一步的上下文 | 顶部**轮次**下拉选轮 → **步骤**下拉选步（末轮多一项 `当前（下一次请求）`） | 右侧按 7 类列出那一步的上下文 |
| 看某一类里都有什么 | 点左边的**类名**展开 | 列出该类每一条（带序号 `#N`、时间、≈token） |
| 改一条 | 在那一行点 **`编辑`** | 行**下面**出现编辑框，里面是**全文**（不是列表里那种 80 字预览） |
| 存下来 | 在编辑框里点 **`保存`** | 行上出现 **`已改（本地）`**；**当前会话的模型看不到** |
| 反悔 | 点 **`丢弃这条改动`** | 该行回到原文，编辑框收起 |
| 把改动带进新会话 | 点 **`开启子会话`**（R5） | 新会话第一句话里逐字带着你改过的正文 |

键盘：编辑框里 **`Esc`** = 取消，**`Cmd/Ctrl + Enter`** = 保存（R3.4）。
每个动作旁边的小 **`?`** 是"这个按钮是干什么的"，不会触发按钮本身（R2.2）。

---

## 3. 七类内容，哪些能改（R2.1 / R2.3）

| 类 | 能不能改 | 为什么 |
|---|---|---|
| **用户消息** | ✅ 能 | 你自己发的话，写错了就该改；本插件的重点 |
| **注入内容** | ✅ 能 | 每轮会被重新注入 → 不改就一轮一轮漂（R2.1） |
| **技能注入** | ✅ 能 | 同上（跟注入内容同族） |
| **工具结果** | ✅ 能（默认收在「高级编辑」后面） | 数量多、改它风险高，所以默认不给按钮（R2.5）。打开顶部的 **`高级编辑`** 就能改 |
| **助手消息** | ❌ 不能 | 平台的硬限制（`docs/01` F7.2）：它既要求"覆盖原文"、又禁止助手消息带这个标记，**两条规则互斥**。要纠正助手的话，就在**开子会话时写在首条任务里** |
| **系统提示词** | ❌ 不能 | 宿主保护（改了会破坏平台自己的约束） |
| **工具定义** | ❌ 不能 | 同上 |

**改不了的行也会说话**：那一行上会有一句人话（`助手消息改不了` / `已被接替` / …），而不是
"有个按钮但是灰的、点了一点反应都没有"（R2.3 / R4.7）。

---

## 4. 只有「编辑」这一种动作（R2.1 的当前口径）

早期设计里有 **批注**（加一段说明）和 **钉住**（把这条固定下来）两种动作。
**现在都没有了** —— 用户 2026-10-02 拍的口径是「上下文的编辑只有编辑就行了」（`docs/11` D19）。
所以界面上每一行最多只有一个动作：**`编辑`**；改过的行多一个 **`丢弃这条改动`**。

为什么砍掉：为了让"我改了什么"永远只有一个答案 —— 就是那条消息的正文本身。
批注和钉住都会引入"正文之外还有一层你的话"的状态，那层话在开启子会话时怎么写进去、算不算
"人类输入"，都是没必要的复杂度。

---

## 5. 保存是**临时**的：什么时候才真的"写进去"（R5 / D15）

保存 = **只写到插件本地**。真正写进会话**只有一次机会**：你点 **`开启子会话`** 的那一刻，
插件的做法是把你改过的每一条**逐字**写进那个新会话的**第一句话**（首条任务）。

- 为什么这样：平台的子会话是从"父会话最后一个**聊完**的轮"切出来的（`docs/01` F38），
  而你在本地做的改动**不在会话日志里** ⟹ 新会话不会自己看到它们。所以必须逐字带过去。
- 因此**开子会话的确认框会写清楚**：从哪儿开始（第几轮末，平台算的，改不了）、会带上什么
  （你改过的正文）、**不会**带上什么（本会话的工具授权、此后新聊的内容）、以及你这次要交给
  它做什么（首条任务，**必须由你自己写** —— 这个项目不允许助手替你生成内容）。
- ⚠️ 边界：如果父会话**还没有任何一个聊完的轮**，子会话**不会继承任何历史**
  （平台侧的种子就是空的，`docs/01` F45）。确认框会如实说明。

## 6. 什么时候**不能**改（R4.3 / R4.7）

| 界面上的说法 | 意思 | 你该怎么办 |
|---|---|---|
| `当前轮次还没结束 —— 改动只能在轮次边界提交。` | 这一轮模型还在跑，上下文随时会变 | 等这一轮结束再改（`保存` 会先禁用，不是点了才报错） |
| `这个会话不在本进程里，只能查看，不能编辑。` | 面板显示的这个会话不归当前进程管 | 切到正在跑的那个会话，或等它被加载进来 |
| `助手消息改不了` | 平台的硬限制（见 §3） | 在开子会话时把要纠正的话写进首条任务 |
| `已被接替` | 这一条已经被后一次改动替换掉了 | 改**当前可见的那条**（可以连续改任意多次） |
| `空内容不行` | 正文删空了 | 留至少一个字；真要去掉这一条，用「丢弃这条改动」回原文 |
| `没有实质改动` | 你保存的内容跟当前生效的一模一样 | 不用保存 |

## 7. 界面上的其它读数（R1.3 / R1.5）

- 顶部 **`比前步 / 比前轮`**：分类行上那两个 **`+N`** 小标，是跟"上一步"还是"上一轮最后一步"比。
  默认**比前轮**（看这一轮整体比上一轮多了/少了什么）。首轮没有可比的对象，就不显示小标。
- 趋势卡标题的 **`按轮次（共 N 轮）`**：让你一眼看出**总共多少轮**，而不是只看到屏幕上那几根柱子。
- **`高级编辑`**：打开后工具结果那类才出现 `编辑`（§3）。
- 统计卡的 **`轮数 / 步数`**：这两个数字就是"面板现在显示的是哪个会话"的凭据 ——
  跟你要对照的那个会话日志里的条数对得上，就是它（`AGENTS.md` §2.5）。

## 8. 术语表（这里出现的每个内部名字）

| 名字 | 对你意味着什么 |
|---|---|
| **轮次（turn）** | 你和模型的一来一回。 |
| **步骤（step）** | 一轮里模型的一次请求。一轮可能有好几步（它先要工具、再要一次…）。 |
| **上下文 / surface** | 这一次请求模型实际读到的全部内容（系统提示词 + 工具定义 + 消息 + 工具结果）。 |
| **注入内容** | 不是你说的话、也不是模型说的话，而是被系统**塞进去**的提示（例如"上次那个会话的摘要"）。 |
| **技能注入** | 上面那类里专门来自"技能"的那些。 |
| **工具结果** | 模型调用工具后拿回来的输出（读文件、跑命令的结果）。 |
| **`#N`（seq）** | 会话日志里每条内容的序号。同一个会话里序号只增不减。 |
| **`已改（本地）`** | 你改过、但**还没**带进任何会话。 |
| **子会话** | 从当前会话切出来的**新会话**，带上你已经聊完的内容，可以续接、可以单独分配模型。 |
| **压缩** | 平台把太长的一段历史换成摘要，腾出空间。被压掉的内容在界面上会标出来。 |

## 9. 常见问题

**问：我保存之后，模型为什么还是按老的内容回答？**
答：因为保存**只到插件本地**（§5）。要让改动生效，得**开启子会话**，在新会话里继续。
这一版不做"直接改写当前会话"（那是另一个动作，需要额外授权，见 `docs/06` §4）。

**问：我能改多久以前的？会不会改了以后又漂回老样子？**
答：可以改**任意轮**里你还能看到的那一条。「注入内容 / 技能注入」这两类每轮会被**重新注入**，
所以它们最容易"漂"；改它们之后**必须**通过开子会话生效，否则下一轮又是老样子。

**问：能改几次？能撤销吗？**
答：**能连续改任意多次**（每次改的都是"当前可见的那条"）。
但界面**不提供版本历史 / 回滚**：那要求先把改动写进当前会话，与"保存只到本地"这条地基冲突
（`docs/11` D19）。

**问：为什么有些行根本没有编辑按钮？**
答：三类原因：助手消息（平台硬限制）、系统提示词与工具定义（宿主保护）、以及被替换掉的老条目。
每一类都会在行上写一句话（§6）。

**问：改动会进到别的会话吗？**
答：不会。改动按会话分开存；只有你点 `开启子会话` 时，才会被写进**那一个**新会话的第一句话。

**问：这个插件需要联网吗？会上传我的内容吗？**
答：不需要、也不上传。改动只写在你自己机器的插件目录里。
