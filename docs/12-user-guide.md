# 上下文批改：用户指南

## 这是什么

「上下文批改」让你查看当前会话中模型实际可见的上下文，并在不改动来源日志的前提下准备一份迁移副本。确认后，插件在当前工作区创建一个零历史普通会话执行任务，并把绑定结果原样送回来源会话。

## 基本流程

1. 打开会话中的「上下文批改」。
2. 查看某一轮 / 某一步的上下文。
3. 可选：逐条编辑或删除材料。保存只写插件本地。
4. 点击「开启普通新会话」。
5. 填写任务，并直接修改「最终发送全文」。
6. 选择执行模型；推理等级可保持「使用模型默认值」。
7. 确认创建。
8. 在左侧会话列表打开新会话；任务完成后，结果会自动回到来源会话。

## 哪些内容可以编辑

| 类型 | 能否编辑迁移副本 | 说明 |
|---|---:|---|
| 用户消息 | 可以 | 来源日志不变 |
| 注入内容 | 可以 | 编辑的是本次迁移副本 |
| 技能材料 | 可以 | 编辑的是本次迁移副本 |
| 助手消息 | 可以 | 不改写历史 assistant/message |
| 工具结果 | 可以 | 需要匹配原工具调用；入口位于高级编辑 |
| 系统提示词 | 不可以 | 由目标预设生成 |
| 工具定义 | 不可以 | 由目标预设和平台生成 |

被遮蔽或已经离开当前 surface 的条目也不可编辑。

## 本地编辑与删除

- `保存`：只写 `$DSH_HOME/dsh-context-redline/`，当前会话模型看不到。
- `丢弃这条改动`：清除本地编辑，恢复来源全文。
- `删除`：表示不迁移该条；来源日志不变。
- `取消删除`：恢复该条参与迁移。
- 编辑正文和删除标记独立保存，因此“编辑 → 删除 → 取消删除”会恢复编辑稿。

## 最终发送全文

确认框会把迁移材料序列化为一个完整用户消息。文本框里的内容就是新会话实际收到的第一句话：

- 可直接删段、改字或重排；
- 确认后逐字冻结；
- 崩溃恢复只重放冻结内容，不重新拼接当前草稿；
- 空文本不能创建。

文本框默认约六行，长内容在框内滚动，也可手动向下放大。

## 模型与推理等级

模型与推理等级位于同一行紧凑选择器中：

- 模型默认沿用来源会话；
- 推理等级默认使用该模型的系统默认值；
- 更换模型会把推理等级重置为模型默认值；
- 选择只影响新会话，不修改来源会话或全局默认；
- 宿主在创建前解析并冻结模型实际默认推理等级，再核对新 Agent 的实际配置。

## 图片和附件

- 文字与图片混合的消息：迁移全部文字，确认框显示「图片 N 个未迁移」。
- 纯图片消息：不生成空白迁移段，但计入遗漏数。
- 图片引用仍参与来源指纹；图片变化后旧确认失效。
- 图片二进制、文件、file-ref 和通用附件目前不迁移。
- 文件类或未知富媒体会明确拒绝，不会静默丢失。

## 什么时候不能创建

创建会被拒绝并显示原因，例如：

- 来源会话不在当前进程；
- 当前轮次尚未闭合；
- 来源或草稿在确认前发生变化；
- 工具结果无法匹配原调用；
- 目标模型或推理等级不可用；
- 工作区、预设或实际 Agent 配置无法核实；
- 台账损坏或冻结内容指纹不匹配。

错误不会自动重试创建，输入会保留。

## 自动回程

插件只取与本次固定 prompt request ID 绑定的任务结果。回程消息形如：

```text
【承载会话结果 · <标题> · <完整会话 id>】
<原样结果>
```

平台原始 `followup` 不提供 request ID 去重，因此插件还会核对精确正文、flush 后的冷日志和持久台账。查询结果为未知时不会盲目重发。

## 常见问题

**保存后，为什么当前模型仍看到旧内容？**
保存只在插件本地。只有确认创建新会话后，迁移副本才进入新会话。

**删除会清除原会话记录吗？**
不会。删除只表示“不迁移这条”。

**为什么图片没有进入新会话？**
当前版本只迁移同一消息中的文字，并明确报告遗漏图片数量。图片二进制迁移尚未实现。

**可以改来源会话的模型吗？**
不会。确认框的选择只配置新会话。
